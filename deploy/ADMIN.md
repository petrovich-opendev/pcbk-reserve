# Инструкция администратора — для ведущего курса

Для того, у кого есть SSH на сервер ПЦБК и доступ к Docker (группа `docker`), без знания кода. Каждый шаг —
готовая команда (места `<…>` заменить своим значением) либо точная ссылка на раздел `deploy/README.md` —
справочника с длинными блоками команд; эта инструкция их не повторяет. Прочитать один раз: README, «Один раз».

## 1. Где что и чего не делать

Всё — в `/opt/pcbk-reserve` на сервере:
- `.env` — настройки выкладки (пути, пороги, переключатели); `chmod 600`.
- `secrets/` (путь — `SECRETS_DIR` из `.env`) — пароли мест, токены, ключи OpenRouter, копия учётки историана
  `bdrv.env`; каталог `0700`, файлы `0444`/`0400`/`0600`.
- `agents/` (путь — `AGENTS_DIR` из `.env`) — агенты студентов; владелец — `core` (uid 10003), с хоста не пишется
  и не переименовывается.
- `data/` (путь — `DATA_DIR` из `.env`) — белый список тегов историана.
- `tls/` — сертификат и ключ входа (копия сертификата Dify).
- `backup/` — резервные копии (раздел 4 и 5 ниже); хранятся две последние.
- `edge/`, `compose.yaml` — компоновка и статика страницы; правит только выкладка.

Страница состояния — `https://<имя сертификата edge>:8443/`. Не в сети ПЦБК — туннель
`ssh -N -L 28443:127.0.0.1:8443 <сервер>`, тот же адрес через `https://127.0.0.1:28443/` (сертификат не совпадёт с
именем — браузер предупредит, это ожидаемо).

**Чего не делать никогда:**
- `docker compose down` на сервере — снимает все десять мест и их сети; `down -v` — к тому же удаляет том журнала
  сторожа;
- удалять тома `pcbk-student-NN-*`, `pcbk-core-data`, `pcbk-watchdog-journal` по отдельности, вне команд README;
- переименовывать или чистить `agents/` и `secrets/` с хоста руками;
- гасить Dify (`/opt/dify`) или писать туда что-либо — он не входит в ваши задачи (раздел 7);
- `systemctl restart docker` — гасит все контейнеры сразу, включая Dify (`reload` — можно, `restart` — никогда).

## 2. Перед занятием — страница состояния

Что значит строка `https://<имя сертификата edge>:8443/` и первое действие на красной (`fail`) или «внимание»
(`warn`) — по идентификатору строки (22 строки `watchdog/components.json`). Тексты — дословно из кода сторожа.

| Строка (id) | Заголовок | Типичный красный/внимание текст | Первое действие | README |
|---|---|---|---|---|
| `edge` | Входной прокси | «сертификат истёк ДД.ММ.ГГГГ» / «до ДД.ММ.ГГГГ (N дн.)» при остатке < 14 дн / «не отвечает» | заменить сертификат | «Замена сертификата» |
| `sp-ro` | Прокси сокета сторожа | «не отвечает» (нет связи с docker.sock) | `docker compose up -d --no-build sp-ro`, затем `docker compose logs sp-ro` | «Выкладка и обновление», шаг 4 |
| `sp-ctl` | Прокси сокета серверного слоя | «нет контейнера» / «остановлен, код N» / «падает в цикле (перезапуски подряд)» | `docker compose up -d --no-build sp-ctl`, затем `docker compose logs sp-ctl` | «Выкладка и обновление», шаг 4 |
| `memory` | Память сервера | «свободно меньше N МиБ» (сбой); «сервер вытесняет память в swap», «давление выше порога», «убивал процессы по памяти вне мест и core» (внимание) | смотреть, что ест память (`docker stats`); не перезапускать демон Docker | «Память сервера» |
| `student-01`…`10` | Рабочее место NN | «нет контейнера» / «падает в цикле…» / «не запускается: …» / «остановлен, код N» / «OpenCode не отвечает» / «нет связи со службой данных (MCP)»; «спит» и «работает» — норма | спящее — ничего не делать (разбудит вход); «нет контейнера» или «остановлен» без видимой причины — `docker start pcbk-student-NN`, затем `docker compose logs pcbk-student-NN`; «настройка рабочего места сломана» — карантин | «Карантин», «Пересоздание мест с сохранением томов» |
| `core` | Служба данных | «не отвечает» / «отвечает ошибкой HTTP N» | `docker compose logs core`; проверить секреты (токены данных) | «Служба данных» |
| `core-container` | Серверный слой — контейнер | то же, что у места (контейнер); «процесс core не отвечает на проверку здоровья» | `docker compose logs core`; если не стартует вовсе — проверить `.env` и секреты (ключи OpenRouter — оба файла) | «Выкладка и обновление» |
| `historian` | Историан БДРВ | «служба данных не отвечает — свежесть неизвестна» / «последняя метка старше N с» / текст ошибки учётки | сначала строка «Служба данных» выше; ошибка учётки — обновить копию `bdrv.env` | «Служба данных» |
| `llm` | LLM-прокси и бюджет | «LLM-прокси не отвечает» / «нет ключа OpenRouter» / «токены LLM не читаются» / «бюджет $N исчерпан» / «прогон остановлен тормозом памяти» | ключи и токены — README «LLM-прокси»; тормоз — «Тормоз прогона по памяти» | «LLM-прокси» |
| `gateway` | Шлюз и вход | «шлюз не отвечает» / «учётные записи недоступны» / «нет связи с прокси сокета — места не будятся» / «вход отклоняется проверкой источника — проверьте GW_ORIGIN» | проверить `.env` (`GW_ORIGIN`), затем строку `sp-ctl` выше | «Вход и рабочие места» |
| `web` | Веб-чат | «страница чата не отдаётся» / «сборка чата неполная» / «не отвечает» | пересобрать и выложить статику заново | «Статика чата» |
| `agents` | Агенты студентов | «настройка рабочего места сломана — место не поднимается» / «каталог агентов недоступен — агенты не сохраняются» / «перезагрузка агентов молчит» | смотреть README «Карантин» и «Файл агента вручную» | «Агенты студентов» |
| `teacher` | Кабинет преподавателя и доли | «журнал действий преподавателя не пишется — кабинет закрыт» / «доли бюджета не загружены — LLM-прокси закрыт для студентов» / «LLM-прокси считает доли не так, как сохранено» | `docker compose up -d --no-build --force-recreate core` (доли и журнал перечитываются с диска) | «Кабинет преподавателя» |

«Внимание» без видимого вреда (например, разовый перезапуск места) обычно гаснет само за срок, названный в самом
тексте строки; не гасит или повторяется — тот же столбец «Первое действие».

## 3. Установка с нуля из поставки

Везде ниже, где стоит «README „раздел“, шаг N», — это готовая команда самого этого шага README, взять оттуда
буквально.

1. gVisor, каталог `/opt/pcbk-reserve`, копия сертификата Dify — README «Один раз», целиком (`sudo`, один раз).
2. Образы на сервер — README «Выкладка и обновление», шаг 1.
3. `compose.yaml` и `edge/` на сервер, копия для отката — README «Выкладка и обновление», шаг 2.
4. `.env` — скопировать `deploy/env.example` в `/opt/pcbk-reserve/.env`, заполнить (обязательно: `DOCKER_GID`,
   `STU_NET`, `TLS_DIR`, `DATA_DIR`, `SECRETS_DIR`, `AGENTS_DIR`; прочее можно оставить пустым — умолчания в самом
   файле), `chmod 600 .env`.
5. Секреты и тома мест — README «Рабочие места», п. 1; на чистом сервере — там же, подпункт «Первая выкладка на
   чистый сервер» (владелец каталога агентов 10003 — одноразовый контейнер от root, только с «да» владельца).
6. Токены данных и LLM, таблицы `core-tokens`/`llm-tokens` — README «Токены данных мест и `core-tokens`».
7. Белый список историана — README «Служба данных» (строит `build_whitelist`, нужен живой доступ к историану).
8. Ключи OpenRouter — README «LLM-прокси», первый пункт (кладёт владелец сам, в своей SSH-сессии).
9. `docker compose up -d --no-build core watchdog edge sp-ro sp-ctl` — README «Выкладка и обновление», шаг 4.
10. Места: `docker compose --profile students create --no-build $(printf 'student-%02d ' $(seq 1 10))`, затем
    `docker compose up -d --no-build watchdog` — README «Рабочие места», п. 2 (именно в этом порядке).
11. Статика чата — README «Статика чата», шаги 1–5 (собирается на машине разработчика).
12. Учётка преподавателя — README «Учётка преподавателя».
13. Проверка: `curl -sk https://127.0.0.1:8443/status.json` → `"stale":false`; страница открывается, строки —
    норма (раздел 2 выше); вход `curl` преподавателем — раздел 9 ниже.

## 4. Обновление на новый выпуск и откат

1. **Резервная копия** — README «Резервная копия и восстановление», разделы «Размер раньше копии» и «Что, куда,
   как», целиком, **до** следующего шага.
2. `cp -p compose.yaml compose.yaml.<прошлый день>` — README «Выкладка и обновление», шаг 2.
3. Новые образы на сервер — README «Выкладка и обновление», шаг 1.
4. `core`: `docker compose up -d --no-build core`; если новый день добавляет ключ в `/health/gateway` — сначала
   сторож (README «Выкладка и обновление», шаг 4, абзац «Порядок `core` и сторожа…»).
5. Сторож: `docker compose up -d --no-build watchdog` (тот же абзац шага 4 решает порядок).
6. Места — README «Пересоздание мест с сохранением томов» (тома сохраняются; кто работает — дождаться конца).
7. `edge` — README «Выкладка и обновление», шаги 2 и 4 (`restart`, если новый шаблон).
8. Статика чата — README «Статика чата», если день её меняет.
9. Проверка — README «Выкладка и обновление», шаг 5, плюс строки раздела 2 выше.

**Откат** — README «Откат», пункт конкретного дня (ищется по имени нового образа, например «Д9а — назад к Д8»);
общие запреты — раздел 1 этой инструкции.

- **По красной строке страницы** — раздел 2 этой инструкции: первое действие — там же.
- **Из резервной копии** (том удалён, файл испорчен, каталог агентов места пропал) — README «Резервная копия и

## 6. Новый студент

- **Обычный путь** — кабинет преподавателя, «Учётные записи» → «Завести студента» (README «Учётные записи у
  преподавателя»): пароль показан преподавателю один раз, вы в этом не участвуете.
- **Без кабинета, командой** — README «Новый студент», первый пункт: `accounts add --login L --role student
  --place N --generate` (пароль печатается один раз) либо тот же `add` с паролем из файла.
- **Занятое место (01–10) — пока нельзя.** Команда и кабинет отвечают текстом «место NN закреплено за учёткой L —
  смена студента в месте только по процедуре владельца»: это осознанное ограничение (README «Новый студент»,
  второй пункт), не ошибка. Что работает сейчас на занятом месте — пробная учётка (README «Освобождение места
  пробной учётки»), тот же человек вернулся (`--same-person`) и включение отключённой учётки (`accounts enable`)
  — команды там же, README «Новый студент».
- **Место 11 и дальше** — не ваша задача: README «Новый студент», пункт «Место 11 и дальше» — к разработчикам.

## 7. Dify и резерв

Независимы (проверено тестом компоновки): если Dify лёг — для резерва делать ничего не нужно, он работает сам.
Общее с Dify — только **копии** двух файлов, снятые один раз: сертификат входа (README «Один раз», п. 2) и учётка
историана `bdrv.env` (README «Служба данных», первый пункт). Обновлять копию — если в Dify сменили сертификат
(README «Замена сертификата») или пароль историана (README «Служба данных», тот же пункт — иначе строка «Служба
данных» держит красным «Историан БДРВ», и служба больше не пробует входить). Регламент окна, когда Dify выключают
целиком для проверки, — README «Прогон без Dify», разделы «Помощники наблюдения» и «Чего не делать»: это окно
владельца, не ваша обычная работа.

## 8. Порт 3389

README «Порт 3389» — там же три варианта решения заказчика (А/Б/В), исходный текст снимаемого правила `ufw`
(записывается в окне В4, которое на момент этой инструкции ещё не проведено) и команды возврата. Ничего не
предполагается заранее: как решится — там же появятся дата, выбранный вариант и результат проверки.

## 9. Проверка входа без браузера

Заголовок — тот же, что шлёт страница входа браузером: `Sec-Fetch-Site: same-origin` (работает всегда, не зависит
от `.env`) либо `Origin:` ровно со значением `GW_ORIGIN`. Пароль — из файла, никогда в командной строке.

```bash
cd /opt/pcbk-reserve
L=<логин> && PWF=<файл с паролем одной строкой> && C=<имя сертификата edge>
python3 -c 'import json,sys; print(json.dumps({"login": sys.argv[1], "password": open(sys.argv[2]).read().rstrip(chr(10))}))' "$L" "$PWF" > /tmp/pcbk-login.json
curl -sk --resolve "$C:8443:127.0.0.1" -c /tmp/pcbk-cookie.txt -H 'Content-Type: application/json' \
  -H 'Sec-Fetch-Site: same-origin' --data-binary @/tmp/pcbk-login.json "https://$C:8443/pcbk/api/auth/login"
```
Что увидите: JSON учётки (`login`, `role`, `place`, …); `401 bad_credentials` — неверный логин или пароль; `429` —
замок входа (раздел 2, строка «Шлюз и вход»).

```bash
curl -sk --resolve "$C:8443:127.0.0.1" -b /tmp/pcbk-cookie.txt "https://$C:8443/pcbk/api/auth/me"
```
Что увидите: ту же учётку и `notice` (у студента — номер непрочитанного предупреждения или `null`; у преподавателя
— всегда `null`). Заголовок источника здесь не нужен.

```bash
curl -sk --resolve "$C:8443:127.0.0.1" -b /tmp/pcbk-cookie.txt -H 'Sec-Fetch-Site: same-origin' \
  -X POST "https://$C:8443/pcbk/api/workplace/wake"
```
Что увидите: у студента — `202` и `{"state":"starting",…}`, повторный `GET` того же пути до `"state":"ready"`; у
преподавателя места нет — `403 no_place`, это ожидаемо.

Убрать за собой: `rm -f /tmp/pcbk-login.json /tmp/pcbk-cookie.txt`.
