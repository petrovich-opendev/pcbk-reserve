# Резервный контур обучения ПЦБК без Dify

Учебный стенд для технологов ПЦБК, не привязанный к Dify. Студент входит в веб под своей учётной записью и в
одном чате разговаривает с «Помощником технолога КДМ-1»: числа из базы данных реального времени (БДРВ) берёт
служба данных стенда, считает код, а не модель. Вторым агентом — «Конструктором» — студент собирает своих
агентов под свой узел процесса. Движок агентов — OpenCode в изолированных контейнерах, модели — через
OpenRouter. Мнемосхемы из исходной постановки не делались.

Рабочих мест 11: десять — студентам, одиннадцатое — учётка-образец `student_test` для живых проверок. Есть
отдельный кабинет преподавателя.

## Что умеет студент в чате

| Функция | Выпуск | Польза для студента |
|---|---|---|
| Поиск тега, текущее и историческое значение, ряд точек | Д3a | Числа БДРВ по имени или описанию, без SQL |
| Наработка оборудования (`calc_runtime`) | Д9a | Время в работе по тегу состояния — готовым расчётом |
| Разбор отклонения от задания (`calc_deviation`) | Д13 | Пары «измерение — задание» и порог технолога за период |
| Живые уточнения (объект, период, база) | Д16–Д17 | Чат переспрашивает, а не угадывает узел или величину |
| Подсчёт агрегатов (`pcbk_equipment`) | Д19–Д19б | Честное «сколько насосов», без домысливания по описаниям |
| Знания V1/V2 на чтение | Д22 | Справка по подготовленным материалам КДМ-1 прямо в диалоге |
| Карта Шухарта, Cp/Cpk (`calc_spc`) | Д21–Д22 | I-MR, X̄-R и 8 правил Нельсона прямо в чате |
| График карты Шухарта | Д24 | Карта рисуется под строкой вызова |
| Поправки к базе знаний (`kb_correction_*`) | Д25 | Нашёл ошибку в знаниях — поправка видна сразу всем студентам |
| Суммарный расход за период (`calc_flow_total`) | Д26 | Трапеции по мгновенным показаниям, пропуски не считаются нулём, покрытие в ответе |
| Расчёт по формуле (`calc_formula`) | Д28 | Сумма, отношение, среднее, корреляция, наклон по 1–4 тегам — вместо отказа |
| Конструктор агентов | Д7 | Свой агент под свой узел с инструментами выше; число тегов не ограничено (Д27) |
| Вкладки «Калькуляторы», «События», «Уроки» | Д9, Д13, Д15a | Расчёты отдельно от чата, журнал действий агентов, учебные материалы |
| Кабинет преподавателя | Д10 | Учётки, доли бюджета на модель, журнал, чтение разговоров |

## Модели

Белый список моделей и их точек — `core/pcbk_core/llm/models.py`; основная и запасная — в `.env` сервера
(`LLM_MODELS`, `LLM_FALLBACK`). При отказе основной модели ядро один раз молча повторяет запрос на запасной.

| Когда | Основная модель мест | Основание |
|---|---|---|
| до 14.10 | `z-ai/glm-5.3` | — |
| Д17, 14.10 | `deepseek/deepseek-v4.1-flash` (точка из списка ZDR), запасная — `z-ai/glm-5.3` | просьба владельца |
| Д18, 15.10 | `anthropic/claude-opus-5.5` (ZDR), запасная — DeepSeek | просьба владельца о самой сильной модели рассуждения; выбор «с ZDR» |
| Д23, 16.10 | `anthropic/claude-fable-5.1` — **без ZDR** | явное решение владельца |
| 16.10 | `deepseek/deepseek-v4.1-flash`, запасная — `z-ai/glm-5.3` | сбои Fable 5.1, решение владельца |

ZDR (zero data retention) — требование к точке модели: данные ПЦБК не оседают у провайдера. В коде
`ModelPolicy.zdr` по умолчанию включён; точка без ZDR разрешается только явным решением владельца на модель.

## Связь с `pcbk-ai-lab`

Dify-стенд, учебный курс и плагин доступа к БДРВ `pcbk_bdrv` — в проекте
`pcbk-ai-lab` (на GitHub — `petrovich-opendev/pcbk-ai-lab`). Код оттуда не переносится:
резерв делается с нуля (решение 17 постановки), проверенные факты об историане
переходят как требования.

## Правила репозитория

* **Производственные данные заказчика не коммитятся**: реестр и значения тегов
  БДРВ, описания процесса и узлов участка, выгрузки историана, материалы курса.
  Они живут на стенде и у преподавателя.
* **Секреты — никогда в git.** Пароль БДРВ, ключ OpenRouter и учётные записи
  передаются только через env-файлы на сервере.
* Личные учётные записи и имена сотрудников заказчика не пишутся.
* **Защищённые файлы КДМ-1** — 19 файлов пакета заказчика (хеши —
  `docs/kdm1/PROTECTED_DATA_BASELINE.current.json`). Правка — только добавлением и по решению владельца на
  задачу, с записью дня в `docs/kdm1/DRIFT.md`; новая арифметика — в незащищённых модулях (`spc.py`,
  `flow.py`, `formula.py`).
* **Ворота имён тегов** — перед каждым коммитом разработчик проверяет изменения на настоящие имена тегов
  предприятия (проверочный скрипт живёт вне репозитория, рядом со списком тегов); в примерах и тестах —
  только вымышленные теги.
* **Живые проверки** — только под учёткой-образцом `student_test` (место 11), не под учётками студентов.
* **Выкладка** — образ собирается из своего дня; перед заменой файлов — копия для отката; места, занятые на
  занятии, не перезапускаются.
