# Резервный контур обучения ПЦБК без Dify

Отдельный продукт для технологов ПЦБК, не привязанный к Dify. Студент входит
в веб своим логином, в чате заводит агентов по своему узлу, агенты берут данные
из БДРВ через общую службу данных. Мнемосхемы в духе PI Vision показывают ход
техпроцесса и события агентов. Движок агентов — OpenCode, модель — через
OpenRouter.

## Состояние

**Д1 готов — 29.09.2026.** На сервере ПЦБК работает резервный стенд первого
дня: страница состояния на порту 8443 (сторож видит входной прокси, два
узких прокси сокета Docker, память сервера и ждёт остальные компоненты),
gVisor установлен без остановки Dify, проба OpenCode под gVisor пройдена,
семь учений наблюдаемости — со снимками в [`docs/checks/D1/`](docs/checks/D1/).
Журнал проверок — [`docs/checks/D1.md`](docs/checks/D1.md), выкладка —
[`deploy/README.md`](deploy/README.md).

Страница: `https://<сервер>:8443/status` из сети ПЦБК (проверить с машины в
сети ПЦБК — хвост Д1); с машины разработчика — через туннель
`ssh -N -L 28443:127.0.0.1:8443 <сервер>` → `https://127.0.0.1:28443/status`.

Сейчас страница красная: сертификат `*.pcbk.ru`, который стоит у Dify и
скопирован на 8443, истёк 21.09.2026 — нужен новый.

Дальше по [дорожной карте](docs/PLAN-platform-2026-09-29.md): Д2 — десять
рабочих мест OpenCode под gVisor, Д3а/Д3б — служба данных БДРВ, потом
LLM-прокси, шлюз, веб-чат и Конструктор.

## Связь с `pcbk-ai-lab`

Dify-стенд, учебный курс и плагин доступа к БДРВ `pcbk_bdrv` — в проекте
`pcbk-ai-lab` (на GitHub — `petrovich-opendev/pcbk-ai-lab`). Код оттуда не переносится:
резерв делается с нуля (решение 17 постановки), проверенные факты об историане
переходят как требования.

## Правила репозитория

* **Производственные данные заказчика не коммитятся**: реестр и значения тегов
  БДРВ, описания процесса и узлов участка, выгрузки историана, материалы курса.
  Они живут на стенде и у преподавателя.
* **Секреты — никогда в git.** Пароль БДРВ, ключ OpenRouter и учётные записи
  передаются только через env-файлы на сервере.
* Личные учётные записи и имена сотрудников заказчика не пишутся.
