# Достоверность и приватность: бот «Подборка для КДМ-1»

Документ для владельца-технолога и для разработчика: как бот проверяет свои утверждения без участия модели и
что из данных уходит во внешние сервисы. Состояние на 16.10.2026 — по коду дня 1 (тег `v0.1.0`/`v0.1.1`); модуль
сборщика (день 2), который вызывает `claude -p`, пока не реализован — описание его проверок в этом документе
помечено отдельно как план.

## 1. Принцип: без цитаты на странице случай в банк не попадает

Защита от выдуманного основания (`docs/specs/2026-10-15-kdm1-digest-design.md`, п.5): случай попадает в банк
только если его цитата-основание, числа и название компании реально найдены в тексте статьи-источника — либо
страница помечается «не сверено автоматически», если её нельзя прочитать без JavaScript или это PDF. Проверки
выполняются одним и тем же кодом для посева вручную (день 1, `kdm1digest/seed.py`) и для будущего автоматического
сборщика (день 2, план) — стандарт один.

## 2. Проверки без модели (`kdm1digest/checks.py`)

**Схема (`validate_case`).** Отклоняется запись, если: не хватает одного из обязательных полей (`implemented`,
`implemented_quote`, `company`, `machine`, `kdm1_node`, `solution_type`, `what_done_ru`, `results`, `relevance`,
`why_relevant_ru`, `source_type`, `published_at`, `title_ru`, `summary_ru`, `details_ru`); `kdm1_node`,
`solution_type` или `source_type` не входят в закрытые списки (`kdm1digest/vocab.py`); `implemented` не равно
`true`; `summary_ru` длиннее 600 знаков; `published_at` — не ISO-дата; в `results` есть элемент без `value` или
без `quote`.

**Сверка со страницей (`check_against_page`), по шагам — отсев на первом несовпавшем:**

| Шаг | Условие отсева |
|---|---|
| 1 | ссылка не открылась (не HTTP 2xx) |
| 2 | `published_at` не разбирается как дата (не ISO) |
| 3 | дата публикации старше 5 календарных лет от сегодня (окно банка) |
| 4 | страница не читается без JavaScript или это PDF |
| 5 | цитата-основание (`implemented_quote`) не найдена на читаемой странице |
| 6 | цитата хотя бы одного элемента `results` не найдена на странице |
| 7 | число хотя бы одного элемента `results` не найдено на странице |
| 8 | значимое слово компании не найдено на странице |

Шаг 4 — особый: это не отсев, а исключение из шагов 5–8. Страница, которую нельзя прочитать без JavaScript,
или PDF, не проверяется по цитатам, числам и компании — случай принимается с пометкой `checks.verified = false`
(«не сверено автоматически»). Окно 5 лет на шаге 3 — решение владельца 15.10 (`docs/TASK.md`, п.14.1); было
12 месяцев.

Нормализация при сравнении: регистр, кавычки всех видов, неразрывные пробелы — схлопываются перед поиском
цитаты. Числа ищутся с учётом разделителей тысяч (пробел, запятая) и десятичной запятой/точки, с границами —
число не засчитывается, если оно на самом деле часть другого числа (например, «15» внутри «150» или «2015»).
Компания ищется по значимому слову названия (без организационно-правовой формы — «AG», «GmbH», «ООО» и т. п.,
без уточнения в скобках вроде города); для кириллических слов длиной от 4 знаков проверяются падежные формы из
закрытого списка окончаний (чтобы «Кама» находила «Камы», «Камой», но не совпадала с «КамАЗ» или «камень»).

## 3. Загрузка страницы (`kdm1digest/linkcheck.py`)

Страница скачивается собственным кодом на `urllib` (без модели и без сторонних библиотек): до 2 МБ, с
определением кодировки по заголовку или `<meta charset>` (откат на `utf-8`), с распаковкой gzip. Видимый текст
извлекается через `html.parser`, без содержимого `<script>`/`<style>`. Страница считается «читаемой», если
видимого текста не меньше 500 знаков; PDF (`Content-Type: application/pdf`) — всегда «не читается» для сверки
(нет текста для сравнения цитат), но сама ссылка может быть при этом рабочей (`ok=True`).

## 4. Защита от повторов (`kdm1digest/dedup.py`)

Это отдельная проверка достоверности — не даёт одному и тому же внедрению попасть в выдачу дважды (критерий
задачи «без повторов», `docs/TASK.md`, п.8, критерий 7):

- **Повтор ссылки** — `url_norm` (нижний регистр хоста, без `www.`, без параметров отслеживания вроде `utm_*`,
  без `#…` и хвостового `/`) совпал с уже сохранённым — тот же случай, запись отклоняется.
- **Тот же случай (`same_case`)** — `case_key` (нормализованная компания | номер машины | узел КДМ-1 | тип
  решения) совпал с существующей записью **и** выполнено одно из: даты публикации отличаются не больше чем на
  120 дней; или совпало хотя бы одно число результата с той же единицей при разнице дат не больше 365 дней —
  запись отклоняется как перепечатка.
- **Возможно, тот же случай (`possible_repeat`)** — `case_key` совпал, но ни одно из условий выше не
  выполнено (например, позднее упоминание без общих цифр) — запись **принимается**, но в выдаче видна строка
  «Возможно, тот же случай, что \<дата\>» (пометка, а не отказ): другой эпизод на той же машине не теряется, а
  скрытый повтор не проходит незаметно.
- Компания нормализуется транслитерацией кириллицы в латиницу (своя таблица), без организационно-правовых форм;
  номер машины — только цифры обозначения (`PM 9` → `9`, `КДМ-3` → `3`).

## 5. Приватность — что уходит во внешние сервисы, что не уходит

| Канал | Что уходит | Что НЕ уходит |
|---|---|---|
| Telegram (день 3, не запущен) | текст выпуска: пересказ, узел, дата, ссылка | токен бота; сообщения не владельцу |
| `claude -p` (день 2, план) | поисковые запросы, тексты открытых статей | данные ПЦБК: БДРВ, документы, корпус |
| Сайты-источники (`fetch`) | HTTP GET с User-Agent браузера | данные бота — на сторону источника |

По `claude -p`: ограничение прямо из принятой задачи (`docs/TASK.md`, раздел 4 «Не входит»: «доступ к данным
предприятия: БДРВ, внутренние документы, корпус КДМ-1»); профиль КДМ-1 для отбора — обобщённый, без номеров
тегов. Токен Telegram-бота маскируется даже в тексте исключений (`telegram.py`), в журналы и вывод не попадает.

**Правила по токену:** `.env` с правами `600`, не в git (`.gitignore`), не в журналах (`journal.py`: «Токен и
chat id сюда никогда не передаются»), не в тексте исключений — слой `telegram.py` явно вычищает подстроку
токена из текста ошибки до того, как оно уйдёт выше по стеку вызовов.

**Данных ПЦБК в боте нет.** Это не только правило дизайна, но и проверенный факт: модуль сборщика, который
обращался бы к внешней модели, в коде дня 1 ещё не реализован (план дня 2), а в текущем коде (банк, выдача,
сторож, посев) ни один модуль не обращается ни к БДРВ, ни к внутренним системам ПЦБК — весь ввод данных о
случаях идёт только через ручной файл посева (`seed.py`) или напрямую со страниц открытых источников.

Отдельная задача `docs/TASK-effect.md` (v4, черновик на согласование владельцу) предлагает считать сценарный
эффект лучших практик по данным БДРВ — но **на учебном стенде** (`pcbk-reserve`), отдельно от этого бота; её
правило: «данные ПЦБК не уходят в бот, в `claude -p` бота и в Telegram без решения Р1» (раздел 8 того
документа). Подробнее — в [план и решения владельца](roadmap-and-decisions.md).

## 6. Стоп-условия (из принятой задачи, `docs/TASK.md`, раздел 9)

Останавливаемся и разбираем причину, если происходит любое из:

- выдуманная статья или ссылка;
- ссылка ведёт не на то, что пересказано;
- искажённая цифра результата;
- два пропуска выпуска подряд без сигнала сторожа;
- бот ответил постороннему, или внутренние данные ПЦБК ушли во внешний сервис.

Дополнительно: по пользе — после 14 дней пробы доля «полезно» ниже 40 %; по реализованности — на контрольной
выборке больше 25 % статей без подтверждённого внедрения; по бюджету разработки — первый работающий выпуск
позже 1 рабочего дня или готовность к пробе позже 3 рабочих дней. Любое из этих условий — повод остановиться и
обсудить с владельцем, а не продолжать молча.
