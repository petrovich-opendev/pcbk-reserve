# Бот «Подборка для КДМ-1»: модель данных

Документ для разработчика и владельца-технолога. Состояние на 16.10.2026. Схема — по
`kdm1digest/store.py` (таблицы) и `kdm1digest/db.py` (доступ); закрытые списки — по
`kdm1digest/vocab.py`; правила повторов — по `kdm1digest/dedup.py`. Статистика — прямой
читающий запрос (`sqlite3 ... mode=ro`) к рабочей копии `~/tg-bot-kdm1/state/
bank.sqlite3`, без выгрузки текстов статей. Архитектура процессов — [architecture.md]
(architecture.md), цель и критерии — [overview.md](overview.md).

## Схема банка (`state/bank.sqlite3`)

Банк — один файл SQLite (WAL), схема создаётся `store.init()`, идемпотентна.

### Таблица `cases`

Один случай внедрения:

| Поле | Назначение |
|---|---|
| `id` | первичный ключ, автоинкремент |
| `url` | ссылка на статью, как в источнике |
| `url_norm` | нормализованный URL (`dedup.url_norm`), уникальна — защита от повтора |
| `case_key` | `company_norm\|machine_norm\|kdm1_node\|solution_type` (`dedup.case_key`) |
| `title_ru` | заголовок на русском |
| `source_name` | название издания/сайта |
| `source_type` | `publisher` / `vendor` / `science` (закрытый список) |
| `lang` | язык источника |
| `published_at` | дата публикации, ISO-строка |
| `company` | название компании, как в источнике |
| `company_norm` | нормализованное название (`dedup.company_norm`) |
| `machine` | обозначение машины/линии из источника, если есть |
| `kdm1_node` | узел КДМ-1, закрытый список (`vocab.KDM1_NODES`) |
| `solution_type` | тип решения, закрытый список (`vocab.SOLUTION_TYPES`) |
| `what_done_ru` | что сделали — на русском |
| `results` | JSON-список `{value, unit, quote}` — цифры результата с цитатой |
| `implemented_quote` | дословная цитата-основание внедрения (≤300 знаков по спецификации) |
| `checks` | JSON `{verified, quote_found, numbers_found, company_found}` |
| `possible_repeat_of` | id прежнего случая при неточном совпадении правила повтора |
| `relevance` | релевантность КДМ-1, целое 1–5 |
| `why_relevant_ru` | почему относится к КДМ-1 — на русском |
| `summary_ru` | краткий пересказ, ≤600 знаков (критерий 6 задачи) |
| `details_ru` | расширенный пересказ («подробнее», план дня 3) |
| `harvest_run_id` | id прогона сборщика; `NULL` — случай добавлен вручную (`seed`) |
| `added_at` | когда случай попал в банк, UTC |
| `sent_at` | когда отправлен владельцу, UTC; `NULL` — ещё не отправлен |
| `rating` | `useful` / `off_topic` / `NULL` — оценка владельца (план дня 3) |
| `rated_at` | когда поставлена оценка |
| `link_dead_at` | когда ссылка оказалась недоступной перед отправкой |

Индексы: `idx_cases_case_key` (по `case_key`), `idx_cases_unsent` (по `sent_at`,
`link_dead_at`) — ускоряют поиск повтора и выбор неотправленных.

### Таблица `runs`

Один прогон сборщика или выдачи: `id`, `started_at`, `finished_at`, `kind` (только
`harvest` или `publish` — CHECK-ограничение схемы), `result` (`ok`/`auth`/`limit`/
`error`), `found`, `checked`, `accepted`, `rejected`, `calls`, `duration_s`, `cost`,
`error`, `details` (JSON, вольные подробности конкретного прогона).

### Таблица `rejects`

Отсеянный кандидат: `id`, `url`, `reason`, `run_id`, `created_at`.

### Таблица `coverage`

Покрытие окна поиска сборщиком (план, пока не используется): `month` (`YYYY-MM`,
первичный ключ), `status` (`pending`/`done`), `done_at`, `accepted`.

### Таблица `deliveries`

Итог одного выпуска: `id`, `day` (дата по Перми), `case_ids` (JSON-список), `message_ids`
(JSON-список), `ok` (0/1), `error`, `created_at`.

## Состояние сторожа (`state/watchdog.sqlite3`)

Отдельный файл — чтобы повреждение банка не лишало сторож памяти. Таблица `alerts`:
`reason` (первичный ключ: `missing_issue`/`harvest_stale`/`low_stock`/`listener_down`/
`bank_broken`), `status` (`ok`/`alert`), `since_utc`, `last_alert_utc`.

## Правила повторов (`dedup.py`)

- **`url_norm(url)`** — нижний регистр хоста, без `www.`, схема `http`→`https`, без
  параметров отслеживания (`utm_*`, `fbclid` и т.п.), без `#...`, без `/` в конце пути,
  оставшиеся параметры запроса сортируются.
- **`company_norm(name)`** — транслитерация кириллицы (ГОСТ 7.79-2000, система Б),
  нижний регистр, без организационных форм (`AG`, `GmbH`, `Ltd`, `ОАО`, `АО`, `ООО` и
  т.п.) и знаков пунктуации.
- **`machine_norm(s)`** — только цифры обозначения машины (`PM 9` → `9`, `КДМ-3` → `3`);
  нет обозначения — пустая строка.
- **`case_key(company, machine, node, solution_type)`** — строка
  `company_norm|machine_norm|kdm1_node|solution_type`: один и тот же случай у одной
  компании на одной машине с тем же узлом и типом решения даёт одинаковый ключ.
- **`find_repeat(conn, candidate)`** — возвращает один из четырёх исходов:
  - `("url", id)` — тот же `url_norm` уже есть в банке (всегда тот же случай);
  - `("same_case", id)` — тот же `case_key`, и (разница дат публикации ≤120 дней, ИЛИ
    совпало хотя бы одно число результата с той же единицей при разнице дат ≤365 дней);
  - `("possible_repeat", id)` — тот же `case_key`, но ни одно из условий выше не
    выполнено (например, позднее упоминание без цифр) — случай принимается с пометкой
    `possible_repeat_of`, в выдаче видна строка «Возможно, тот же случай, что ...»;
  - `("new", None)` — ни URL, ни `case_key` не совпали.

Семантика: перепечатки одного случая на разных сайтах склеиваются (`same_case`), а
другой эпизод на той же машине (например, второй проект по прессовой части через год)
не теряется — проходит как новый случай или помечается `possible_repeat` без потери.

## Окно банка (5 лет) и пометки «архив» / «новое»

- **Окно банка — 5 лет** (`checks.BANK_WINDOW_YEARS = 5`): случай с `published_at`
  старше `today` минус 5 календарных лет в банк не попадает (`checks._bank_cutoff_date`,
  отказ «дата старше 5 лет»). Решение владельца после дня 1 (`docs/TASK.md`, п.14.1) —
  было «последний год» в исходном дизайне.
- **«Новое»** (`publish.NEW_WINDOW_DAYS = 14`): случай помечается «новое» в выдаче, если
  `published_at` не старше 14 дней от даты выдачи (по Перми).
- **«Архив»**: случай помечается «архив», если он не «новое» И старше 365 дней
  (`publish._augment_for_render`). Случаи между 15 днями и годом — без пометки.
- Пометки взаимно исключают друг друга: у «нового» случая `is_archive` всегда `False`.

## Что хранится в `results`

`results` — JSON-список объектов вида `{"value": ..., "unit": ..., "quote": ...}`:
каждое число результата (например, снижение расхода пара в процентах) — с единицей
измерения и дословной цитатой-основанием с языка источника, без перевода. Цитата
каждого элемента сверяется со страницей (`checks._results_quotes_found`), число — через
`checks.numbers_found` с нормализацией разделителей тысяч и десятичной запятой/точки.
Пример структуры (без реальных данных банка): `{"value": "12", "unit": "%", "quote":
"..."}`.
