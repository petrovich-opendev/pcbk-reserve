# Альтернативы связке NVIDIA NemoClaw + Open WebUI

19.10.2026 · продолжение [12-nemoclaw-open-webui-2026-10-19.md](12-nemoclaw-open-webui-2026-10-19.md).
Исследование по первоисточникам: документация, GitHub, файлы LICENSE, официальные блоги и прайсы. Ключевые
факты проверены отдельным проверяющим, выводы — критиком. **[Д]** — подтверждено по ссылке, **[?]** — не
подтверждено.

Ограничения, под которые подбирались варианты:
- ВМ VMware: 8 vCPU / 15 ГБ, без GPU, без вложенной виртуализации; рядом Dify заказчика;
- Россия;
- класс 10–20 человек, роли, чтение разговоров преподавателем;
- русский язык;
- наши MCP-инструменты историана;
- графики процесса;
- данные процесса не уходят провайдеру.

## Коротко

1. **Рекомендую развивать текущую архитектуру.**
   - Места OpenCode под gVisor — единственная изоляция агентов, которая работает в обычной ВМ без KVM [Д].
   - Плюс **слой дашбордов Grafana** для графиков процесса.
   - Плюс **российский провайдер моделей** в нашем LLM-прокси: Yandex AI Studio или Cloud.ru. Он закрывает
     сбои сети до OpenRouter и требование «данные в РФ».
   - Плюс исправления по ревью кода.
   - Цели заказчика («агенты в безопасной среде» и «визуализация») этим закрываются без альфа-продуктов и без
     GPU.
2. **Если заказчику нужен готовый интерфейс** вместо нашего чата — Open WebUI или **LibreChat** поверх нашего
   `core`. LibreChat штатно подставляет пользователя в наши MCP-инструменты, лицензия MIT. Ни один из них не
   даёт изоляции агента на студента: это делает только наш вариант с местами.
3. **Dify заказчика** технически ближе всех готовых платформ. Но стенд создавался как резерв, работающий, когда
   Dify лежит, — перенос на Dify эту задачу отменяет. Плюс ограничения лицензии Dify.
4. **Локальные модели — только с GPU.** На 8 vCPU агенты для класса не потянуть. С GPU — открытые модели с
   хорошим русским под нашим LLM-прокси, без NVIDIA-облака.

## Что выяснили по слоям

### Среда агентов и изоляция (вместо NemoClaw/OpenShell)

| Вариант | Годится | Почему |
|---|---|---|
| **Текущий: OpenCode на студента под gVisor (runsc)** | **да** | gVisor на платформе systrap работает внутри обычной ВМ без KVM; разработчики gVisor прямо советуют systrap для запуска в ВМ [Д]. Уже работает на этой ВМ. Оркестрация мест — наш код |
| NVIDIA OpenShell без NemoClaw | нет (пока) | Apache-2.0, стабильная линия 0.1.x [Д]. Несколько пользователей ОС на одном хосте — открытая задача разработчиков (issue #4273, 07.10.2026) [Д] |
| OpenHands | нет | Сам проект: не для многоарендности, нет встроенной аутентификации и изоляции [Д]. По их расчёту ~5 одновременных песочниц требуют 8 vCPU / 32 ГиБ [Д] |
| e2b, Kata Containers, Firecracker, microsandbox | нет | Нужен KVM: bare metal или включённая вложенная виртуализация [Д]. На ВМ заказчика её нет |
| Daytona | нет | С июня 2026 управляющая часть закрыта, открытый код заморожен на v0.190.0 без патчей [Д] |
| Letta, Agno AgentOS, LangGraph, OpenAI Agents SDK, Google ADK | как каркас — да, как изоляция — нет | Это каркасы агентного сервиса, а не песочницы. Letta хорошо держит «агент на пользователя» и MCP с заголовками авторизации [Д]. Исполнение кода отдаёт во внешний e2b — снова KVM. У LangGraph своя аутентификация — только в платной редакции [Д] |

**Нужна ли песочница вообще.** Если агент пользуется только фиксированными MCP-инструментами (сейчас так и есть),
исполнения кода от имени студента нет. Угроза — модель или обработанный текст, который пытается выйти за рамки
инструментов. От неё защищают сами инструменты: белый список тегов, ворота, пределы. Песочница становится
обязательной, когда студенту дают писать и запускать свой код.

### Интерфейс чата (вместо Open WebUI)

| Вариант | Годится | Почему |
|---|---|---|
| **Свой React-чат (текущий)** | **да** | Уже есть роли, чтение разговоров, сборка агента диалогом, передача личности в MCP, карта Шухарта с графиком, бюджет. Лицензия MIT |
| **LibreChat** | частично — лучший из готовых | Роли и ACL, администратор видит все разговоры; подстановка пользователя в MCP (`{{LIBRECHAT_USER_ID}}`, `{{LIBRECHAT_USER_EMAIL}}`, передача OAuth-токена) [Д]; MIT. Нет графиков процесса. Сборщик агентов — форма, не диалог. Бюджет по студенту не подтверждён [?] |
| Open WebUI | частично | См. документ 12: роли, MCP, артефакты; нет принудительного бюджета; исполнение кода по пользователю — по корпоративной лицензии |
| LobeHub (LobeChat) | слабо | Многопользовательский режим, MCP, артефакты. Лицензия LobeHub Community License ограничивает модификацию и ребрендинг без договора [Д]. Задача о непередаче авторизации в MCP (#19878) закрыта автором без исправления — статус проблемы не ясен [?] |
| AnythingLLM | слабо | MIT, роли, агенты. Заголовки MCP статичны — личность пользователя не подставляется [Д] |
| Chainlit | нет | Репозиторий архивирован 15.10.2026 [Д] |
| Интерфейс Dify | частично | Уже стоит, графики ECharts в ответах. Нет сборки агента студентом. Переменная пользователя в заголовках MCP — открытый запрос [Д]. У рендера ECharts была XSS (CVE-2026-26023); версию исправления сверить по официальному advisory [?] |

### Визуализация процесса

| Вариант | Годится | Почему |
|---|---|---|
| **Grafana** | **да** | Коннектор MS SQL в режиме только чтения, встраивание панелей, вход через заголовок от нашего шлюза (`auth.proxy`), русский интерфейс, скромные ресурсы [Д]. Лицензия AGPLv3 — без правок исходников использовать можно; правки — с юридической проверкой |
| Apache Superset | частично | Apache 2.0, встраивание с гостевыми токенами [Д]. Тяжелее: 4+ vCPU / 8 ГБ плюс Postgres и Redis — на общей ВМ рискованно |
| Perses, Metabase | не проверены | Названы критиком как возможные лёгкие альтернативы без AGPL |

**Важная оговорка.** Наша служба данных пускает к историану только теги белого списка, через ворота и бюджет.
Grafana, подключённая к MS SQL напрямую, эти правила обходит. Варианты:
- отдельная учётка БД только для чтения с ограниченными представлениями — делает администратор БД заказчика;
- Grafana читает наше HTTP API `/api/data/*` через плагин JSON-источника — белый список сохраняется [?] (проверить
  пилотом).

### Модели в РФ (вместо облака NVIDIA и вдобавок к OpenRouter)

| Вариант | Годится | Почему |
|---|---|---|
| **Yandex AI Studio** | **да** | OpenAI-совместимый API [Д]. Открытые модели (DeepSeek, Qwen3, gpt-oss) с вызовом инструментов. **По умолчанию модели сохраняют все данные запросов.** Отключается заголовком `x-data-logging-enabled: false`; с ним содержимое не используется для улучшения сервиса [Д, [документация](https://aistudio.yandex.ru/docs/ru/ai-studio/operations/disable-logging)]. Наш прокси может ставить заголовок на каждый запрос. Соответствие 152-ФЗ и сроки хранения — сверить по договору [?]. Подключение — 1–2 дня |
| **Cloud.ru Foundation Models** | да, с проверкой | OpenAI-совместимый эндпоинт, модели на российских серверах, широкий каталог (GigaChat, DeepSeek, Qwen и др.) [Д]. Не найдено заявления «данные не используются для обучения» — проверить договор [?]. 1–2 дня |
| GigaChat API (Сбер) | частично | Сильный русский, вызов функций. Не совместим с OpenAI напрямую — нужен адаптер `gpt2giga`, OAuth, договор [Д]. 2–4 дня |
| Российские перепродавцы зарубежных моделей | нет | Данные всё равно уходят за рубеж |
| Свои модели на CPU (8 vCPU) | нет | Ориентировочно 10–20 токенов/с на один поток для модели 7–8B; для 11 агентов с многошаговыми вызовами инструментов мало [?] |
| Свои модели на GPU | при покупке железа | Открытые веса с хорошим русским: Qwen3, GigaChat 3 (MIT) и др., через vLLM — OpenAI-совместимо, под наш прокси. Не зависит от NVIDIA-облака; закупка GPU в РФ — отдельный риск |
| LiteLLM | не обязателен | Готовые бюджеты и маршрутизация [Д], но дублирует наш прокси. Нужен, только если откажемся от своего |

Подключать российского провайдера стоит **сначала запасным** в уже существующем механизме `LLM_FALLBACK` и
проверить на тех же сценариях отбора моделей (`bench/`). Потом решать, делать ли его основным.

### Готовые платформы целиком

| Платформа | Годится | Почему |
|---|---|---|
| Dify (уже у заказчика) | технически — частично | Роли, логи разговоров, MCP в обе стороны с подстановкой заголовков запроса, графики ECharts [Д]. | n8n | нет | Лицензия прямо запрещает давать внешним пользователям собирать свои сценарии через UI, API, MCP или ИИ-агента [Д] — это наш сценарий |
| Yandex AI Studio (агенты, MCP Hub) | облако — да; у себя — нет | Своя установка — отдельный программно-аппаратный комплекс с GPU через партнёров [Д] |

**Вариант 1 по дням** (каждый день — видимый результат):
1. Российский провайдер запасным в LLM-прокси (заголовок отключения логирования) и прогон `bench`.
2. Решение по провайдеру: основной или запасной.
3. Grafana в compose, вход через наш шлюз, первая панель «ряд тега за смену».
4. Источник Grafana с белым списком (наше API или представления только для чтения), дашборд узла КДМ-1.
5. Ссылка на панель Grafana из ответа агента и из «Калькуляторов».
6–8. Пакеты П1–П3 промпта улучшений по ревью (база, сеть до модели, наблюдаемость) — параллельно или следом.

**Вариант 6 — пилот NemoClaw для одного агента оператора** (из документа 12) совместим с любым из вариантов 1–4,
если заказчику важно видеть NemoClaw в архитектуре.

## Что сказать заказчику

Цели связки NemoClaw + Open WebUI достижимы, но другими средствами — проверенными и работающими на текущем
сервере:

- **«Агенты в безопасной среде»** — уже есть: агент каждого студента в своём изолированном контейнере (gVisor)
  без интернета. NemoClaw этого для класса не даёт.
- **«Визуализация»** — карта Шухарта уже рисуется в чате; дашборды процесса — Grafana.
- **«Надёжные модели без вывоза данных»** — российский провайдер (Yandex AI Studio или Cloud.ru) с отключённым
  журналированием запросов, под нашим прокси с бюджетом и белым списком моделей.
- **«Готовый интерфейс»**, если нужен именно он, — Open WebUI или LibreChat поверх наших служб, ценой изоляции
  агента на студента.

## Вопросы заказчику

1. Что важнее в «NemoClaw + Open WebUI»: изоляция агентов, готовый интерфейс, NVIDIA как бренд или локальные
   модели?
2. Будут ли студенты писать и запускать свой код? От этого зависит, нужна ли песочница исполнения кода.
3. Допустим ли для заказчика российский облачный провайдер моделей (Yandex, Cloud.ru)? С каким договором?
4. Даст ли администратор БД учётку только для чтения с ограниченными представлениями для Grafana, или Grafana
   должна читать только через нашу службу данных?
5. Остаётся ли требование «стенд работает без Dify»?
6. Будет ли GPU-сервер — когда и какой?
