## Задача 0. Утренняя проба

### Предпроверки
- `kernel.yama.ptrace_scope` = 1 — gVisor (systrap) работает. [П]
- AVX2 есть — сборка OpenCode `opencode-linux-x64` (не `-baseline`). [П]
- Docker 29.7.2, cgroup v2, драйвер systemd, хранилище образов — containerd
  (snapshotter), `userns` не включён, `live-restore` выключен. [П]
- `ExecReload` у docker.service — `kill -s HUP`; `daemon.json` не менялся
  после старта dockerd — reload не применит чужих отложенных правок. [П]
- Порт 8443 свободен; сетей Docker в 172.31.0.0/16 нет; маршрут к историану
  идёт через шлюз. [П]

### gVisor
- Установлен release-20260921.0 (sha512 тарбола сошёлся), `runsc install --
  --platform=systrap`, `dockerd --validate` — `configuration OK`,
  `systemctl reload docker` — runtime `runsc` подключён. [П]
- **Ни один контейнер Dify не перезапускался**: время старта всех
  контейнеров до и после совпало. [П]
- Откат: `/etc/docker/daemon.json.pre-runsc` → на место, `systemctl reload docker`.

## Сертификат `*.pcbk.ru`

Сертификат, которым Dify отдаёт HTTPS на сервере (копия — в
`/opt/pcbk-reserve/tls`), **истёк 21.09.2026**. [П] Страница состояния
покажет «Входной прокси — сертификат истёк». Если пользователи ходят к стенду
через корпоративный прокси ПЦБК, который подставляет свой сертификат, они
этого не видят; прямые обращения к серверу получают ошибку сертификата.
Вопрос владельцу: где взять новый сертификат.

## Задача 6. Живые проверки и учения

### Прокси сокета
- `sp-ctl` (клиент `pcbk-core`): осмотр и запуск рабочего места — пропуск
  (404: места ещё нет); список контейнеров, осмотр и остановка контейнера
  Dify, create, exec, `start/../../create`, volumes, images — 403; DELETE —
  405; чужой клиент — 403. [П]
- `sp-ro` (изнутри сторожа): осмотр своих — 200; список, контейнер Dify, logs,
  events — 403; POST — 405. [П]
- Сокет Docker смонтирован только у `pcbk-sp-ro` и `pcbk-sp-ctl`; наружу
  опубликован только 8443 у `pcbk-edge`. [П]

### Сети
- `pcbk-front`, `pcbk-ro`, `pcbk-ctl` — внутренние, изолированный шлюз,
  адресов IPv4 на мостах нет; `pcbk-public` — маскарад выключен. [П]
- Из `pcbk-ctl`: положительный контроль (`sp-ctl:2375`) — открыт; сервер в
  ЛВС 22 и 443, интернет — закрыты. [П]
