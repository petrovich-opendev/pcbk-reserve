## Итоговая доводка Д7а

Итоговое ревью ветки (Important 3, Minor 4) и отложенное по задачам А3, А4,
А5, А7 — одним раундом. Всё ниже — локально, не на сервере.

- **Флаг сбоя учёта снимается сам (I-1).** `save_agent` снимает флаг при
  любом ответе учёта, кроме `StoreError`: `saved`, `already`,
  `name_taken`, `too_many_agents` и `DirUnavailable` (`save` читает строки
  раньше каталога — это сбой каталога, а не учёта). Роль «данные» раз в
  `EVENTS_CHECK_S` (30 с) вместе с проверкой журнала событий открывает учёт
  заново (`open()`) и пробует запись с откатом: на файле `core.db` только
  для чтения `open()` проходит (`BEGIN IMMEDIATE` и `CREATE … IF NOT EXISTS`
  ничего не пишут), а запись — `SQLITE_READONLY`. В журнал службы — только
  смена «запись не проходит / снова проходит»; прежнее состояние флага
  читается после проверки, так что сбой `save_agent` за время проверки
  смену не прячет. Один `SQLITE_BUSY` больше не держит `fail` «учёт агентов
  недоступен» в баннере до перезапуска `core`. [Л]
- **`error` считается как `unavailable` (I-2)** — см. «Отступления от
  плана». [Л]
- **Откат Д7а → Д6б (I-3б)** — раздел «Откат» `deploy/README.md`: `core` и
  сторож вместе, владелец каталога агентов — прежний из снимка утра (иначе

## Отступления от плана

- **`error` у `save_agent` считается как `unavailable`** (итоговое ревью Д7а,
  I-2). Д7-R57: «счётчики `saved`, `refused`, `unavailable`» — у `error`
  счётчика не было. Это пробел плана против правила «ловить молчание»: при
  сплошных сбоях (`render_failed`, непредвиденное исключение) строка
  «Агенты студентов» оставалась бы `ok` «агенты сохраняются». Теперь каждый
  исход `error` поднимает `unavailable_1h` → `warn` «save_agent отвечает
  «недоступно» — агенты не сохраняются». Договор `/health/agents` (15 ключей)
  не меняется. Вызов, отменённый клиентом, пока ждал замок места (две
  записи одного места разом), — событие `error: cancelled`, в счётчик не
  идёт, строка журнала — WARNING: отмена клиентом — не сбой службы.
