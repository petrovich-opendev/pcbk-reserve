## Что сделано

- Служба данных: инструмент `equipment(query, with_state=False)` → в местах `pcbk_equipment`. Теги белого списка
  группируются по основе имени (имя без последнего `_ХВОСТА`); агрегат — основа хотя бы с одним сигналом привода или
  состояния (`RUN, LOD, SPD, CUR, OP, OPN, CLS, ON, OFF, STOP, FLT, ALM`), прочие основы — точки измерения (считаются
  отдельно). Ответ — число агрегатов, тегов, точек измерения, группы по префиксу кода, полный список до 300. С
  `with_state` служба читает `_RUN` тем же путём, что `tag_now`: «работает / стоит / нет данных / нет тега работы» и
  пометка «не менялось больше суток»; больше 120 агрегатов с `_RUN` — отказ с просьбой сузить запрос.
- Агенты: AGENTS.md п.8 — «Все теги стенда относятся к КДМ-1. Вопрос „сколько …“ — вызови pcbk_equipment и назови его
  число как есть; сам по спискам поиска не считай» (решение владельца «весь каталог — КДМ-1»). Помощник —
  `pcbk_equipment: allow`, шестое умение; Конструктор и агенты студентов (`AGENT_TOOLS`, save_agent) — с equipment.
- Защищённые файлы пакета КДМ-1 (`catalog.py`, `service.py`, `mcp_server.py`) — только добавления, решение владельца
  «Разрешить добавление»; база `docs/kdm1/PROTECTED_DATA_BASELINE.current.json` пересчитана, `docs/kdm1/DRIFT.md`
  раздел Д19.
- Хвост Д18: тест bench `test_config_refs_from_opencode_json` — отрицательный пример модели заменён на Fable 5.1.

- Совпадение по слову в любом месте описания: «Клапан … после насоса», «вентилятор … двигателя насоса» тоже считаются
  агрегатом по запросу «насос» — число завышено, агент об этом оговаривается. Предложено уточнение (Д19б).

  ответа сказано.
