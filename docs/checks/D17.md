## Что сделано

- **Телеметрия в ответе.** Новая серверная секция `telemetry_observation` («Данные историана») — расширение контракта
  заказчика по мастер-промпту §7 п.7 (`docs/kdm1/DRIFT.md`). Подпись оборудования из вопроса → согласованная связь
  (`reviews.resolved_link`, проверка в момент ответа) → прежний `DataService` (`data_bridge`, тот же, что у калькуляторов)
  → шаблон: значение (до трёх знаков), единица или «(единица в историане не задана)», время в поясе историана,
  качество, кто согласовал; за период — среднее/минимум/максимум/доля хороших точек. Без связи, при уточнении, команде
  и отказе — чтения нет; отказ службы данных — как есть; в LLM телеметрия не уходит. Вопрос только о подписи — без
  полнотекстового пакета и вызова модели.
- **«Связи с историаном».** `GET /pcbk/api/analytics/links`, `GET …/links/{id}/candidates` (поиск по разрешённому
  каталогу), заявка `equipment_link` с проверкой id связи и имени тега; раздел вкладки с подбором тега (`…_PV` факт /
  `…_SP` задание) и отправкой на согласование; в заявках — подпись оборудования.
- **Уточнения (живые вопросы).** Фраза узла с головой названия и в пределах предложения важнее пословного совпадения
  («уровнемер в машинном бассейне» → выбор из двух бассейнов); точная фраза термина («машинное направление» — без
  уточнения); «КДМ-1» и числа-значения с единицами — не номера узлов; фраза узла + номер — пересечение; период из
  формы снимает уточнение периода у разбора отклонения (с Д16 разбор с периодом всё равно просил период); одиночный
  спорный термин-величина, чувствительная к базе (влажность, вакуум, концентрация массы), — без «какая величина»,
  остаётся вопрос базы, прочие спорные термины (Верх, Низ, ПЦ/ЦВВ, Глинозем…) — как в Д16; «по массе/по объёму» —
  выражение базы только рядом с базочувствительной величиной или «N %»; перечисление («Какие машинные бассейны…», T-01)
  — без выбора узла; точная подпись оборудования снимает уточнение величины/базы (кроме расчётов); «кубов в час»;
  «заблокируй(те)» — команда.
- **Расхождения источников.** Открытые расхождения корпуса узлов вопроса показываются плашкой, ответ получает
  `source_conflict` — в вебе «Отправить на согласование» (пробел Д16: код был объявлен, но не выставлялся).
- **Строгий формат ответа модели.** Аналитика слала `response_format.json_schema` без обёртки `name/strict/schema`:
  DeepInfra отвечал 422, Fireworks молча игнорировал схему — выбор модели с Д16 не проходил строгий разбор, ответы
  строились справкой без модели. Теперь обёртка по формату OpenAI/OpenRouter, без `uniqueItems` (уникальность и
  пределы перепроверяет сервер, мастер-промпт §8). После правки модель реально выбирает карточки — ответы точнее.
- **Сокращения из Dify ПЦБК.** 26 из 30 — новая версия корпуса `2026-10-14-dify` (2.0:eff182e8f09f817e): источник
  `LOCAL-DIFY-KB`, карточки-определения `DEF-dify-*`, термины `dify-*` (только сами сокращения, без русских
  многословных псевдонимов). Не добавлены — нет расшифровки ни в Dify, ни в корпусе: Dlt, АСУТП, КБЦ-1, BVG; «СВЧ» в
  Dify не найдено. В вебе раздел местного источника — «внутренний источник», не «публичный».
- **Основная модель DeepSeek.** Белый список прокси: точка `deepinfra/fp8` (в списке ZDR OpenRouter), цены без скидки
  0,3 — 0.20/0.60 за 1 млн, effort high (= reasoning enabled для этой модели), `reasoning_details` прокси пропускает;
  значения `.env` и мест — `deploy/README.md`, «Модели по ролям».
- **Мелочи.** У ограничений и уточнений без ссылок нет строки «Без оснований»; у телеметрии — строка источника
  (служба данных); в текстах расчёта нет служебных ссылок; `docs/kdm1/CORPUS_OPERATIONS.md` — порядок публикации
  при второй версии корпуса (без `CURRENT` core открывает самую новую папку).

## Известные ограничения

- «верхней/нижней сетки» вне названия узла уточняется как «Верх/Низ» — так задумано в корпусе заказчика (T-12);
  внутри названия узла («машинный бассейн верхней сетки №8») — без уточнения.
- Секция расчёта показывает внутренние имена формулы и входов (`dry_solid_flow`, `volumetric_flow_m3_h`).
- Ответы с моделью — до минуты и дольше (рассуждение high); расчёт и телеметрия считаются сервером.
- Подпись оборудования ищется точным совпадением (регистр, знаки); до трёх подписей на ответ.
- Единичный 503 `pcbk_ledger` («database is locked» журнала вызовов) при всплеске — повтор проходит (механизм Д4а).
- `GET …/links` — по вызову `resolved_link` на каждую связь (~52 мс на 67 связей).
- Пакет заказчика: 120 против 130 сценариев и 11 открытых противоречий корпуса — за технологами.
