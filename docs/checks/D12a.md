**I-7 (ключевой пункт).**

1. **`run` на `ServerStand` требует поля базы окна (`RunRefused("window_base")`) вне `load`?** — **Нет.** Проверка
   строго под условием `cfg.load`:
   ```
   bench/pcbk_bench/__main__.py:387-391
       if cfg.load:
           if cfg.load_data == "twin":
               raise RunRefused("load_data")
           if any(getattr(cfg, key) is None for key in WINDOW_BASE_KEYS):
               raise RunRefused("window_base")
   ```
   Вне режима нагрузки (`cfg.load` ложно) поля базы окна (`WINDOW_BASE_KEYS`, `bench/pcbk_bench/config.py:46`) не
   требуются вообще.
2. **Идёт ли `MemoryGuard`/`dify_swap_mib()` вне `load`?** — **Нет.** `_prepare_load()` (создание `MemoryGuard` и
   опрос `dify_swap_mib()`, `bench/pcbk_bench/load.py:338-440`) вызывается только здесь:
   ```
   bench/pcbk_bench/runner.py:504-505
       if self.cfg.load:
           self._prepare_load()
   ```
   Вне режима нагрузки прогонщик вообще не обращается ни к `MemoryGuard`, ни к `stand.dify_swap_mib()`.
3. **Что отдаёт `dify_swap_mib()` при нуле контейнеров не `pcbk-*`?** — **Не 0 — исключение.** Команда стенда:
   ```
   bench/pcbk_bench/stand.py:83-84 (_DIFY_PIPE)
       docker ps --no-trunc --format '{{.ID}} {{.Names}}' | awk '$2 !~ /^pcbk-/ {print ...}' | xargs -r cat
   bench/pcbk_bench/stand.py:323-334 (dify_swap_mib)
       lines = self._ssh(DIFY_SWAP_SH, ...).split()
       if not lines:
           raise StandError("swap Dify: контейнеров не pcbk- не видно")
   ```
   Если контейнеров не `pcbk-*` нет (Dify остановлен целиком), `awk` не печатает ни одной строки, `xargs -r` с
   пустым входом **не запускает** `cat` — `_ssh(...)` возвращает пустую строку, `lines == []`, и метод **бросает
   `StandError`**, а не возвращает `0`. Внутри `MemoryGuard._poll` (`load.py:411-416`) одно такое падение
   перехватывается `_read` (`load.py:394-405`) и просто считается «неудачное чтение» (`_dify_fails += 1`), но после
   `DIFY_FAIL_LIMIT = 3` подряд неудачных чтений (`load.py:66`, опрос swap Dify — раз в `DIFY_POLL_S = 15` с,
   `load.py:64`) вердикт становится `"blind"` (`load.py:328`) → жёсткая остановка (`HARD_VERDICTS`, `load.py:106`;
   в `_prepare_load` первый же «слепой» опрос останавливает подготовку, `runner.py:584-586`).
   **Следствие для А2/А3/Б0–Б2:** проверка «Dify остановлен» через `ServerStand` **не может** полагаться на то, что
   `dify_swap_mib()` в точности в сценарии «Dify выключен целиком» вернёт `0` как признак успеха — в этом сценарии
   вызов **падает**. Двойник Dify в А2 должен явно обрабатывать это падение (трактовать `StandError`/пустой ответ
   конвейера как «Dify остановлен», а не ждать числового `0`), либо не использовать голый `dify_swap_mib()` для
   этой проверки вовсе. Поля базы окна (`window_base`) при этом по-прежнему не нужны — они проверяются только под
   `cfg.load`, а проверка «Dify остановлен» в А2 режим нагрузки не включает.
