### Известные ограничения (ревью А6, записи без кода)

- **m-1. Студенты не видят прочие `fail` строки агентов, пока
  `image_config_1h > 0`.** `image_config_1h > 0` стоит первым в таблице
  Д7-R60: при нём строка «Агенты студентов» — `fail` «настройка рабочего
  места сломана», и этот `fail` баннер студента скрывает (`OWNER_FAILS`,
  `web/src/status.ts`). Если в тот же час сломается каталог или учёт агентов,
  строка останется с текстом `image_config`: студенты час не увидят и этот
  сбой. Владелец видит строку `fail` на странице сторожа.
- **m-2. `StoreError` + `not_visible` + повтор черновика → `already`.** При
  сбое учёта после переноса в карантин строка агента остаётся `saved`. Следующая
  перезагрузка делает её `not_visible`, а повтор того же черновика отвечает
  `already`: «сохранено» про агента, которого место не видит. Нужны сразу три
  редких события; панель покажет «не загрузился».
- **m-3. Экземпляр места сломан после трёх `no_answer`.** После `dispose` все
  три `GET /agent` молчат, и экземпляр оказывается сломан. Место остаётся
  «готово»: ходы студента получают 400 места. Шторма `dispose` нет:
  `/session/status` сломанного экземпляра не отвечает пустой картой (400).
  Место погасит уборщик по
  простою, починит следующее пробуждение (там `repair`).
- **m-4. Тест учения строки и Chrome.** Тест от Chrome не зависит: снимок —
  только при `PCBK_SHOTS`, через `cdp.Browser()`, как `test_agents_row_ok`.
  Без Chrome тест идёт целиком, без снимка.
- **m-5. До трёх карантинов за цепочку «воркер → пробуждение».** Воркер уносит
  первый файл, перезапуск. Пробуждение встречает второй — `repaired`, один
  повтор. Третий файл в том же пробуждении — `config`: место гаснет, текст
  «Настройка рабочего места сломана — сообщите администратору.». Это в пределах
  Д7-R59: не больше 3 карантинов за час на место.

### Решения А6 сверх плана

- **`watchdog:d7a` сверяется по слоям, не по ID.** В компоновке Д7б сторож
  собирается с тегом `:d7a`, и `up --build` фикстуры пересобирает его каждым
  прогоном: ID меняется при той же сборке, как у образа места. Эталон слоёв:
  `RootFS` `e95b7ceb0e12e5d8`, `Config` `a56edfc912b5b57c`. Содержимое `/app`
  совпадает с `watchdog/` головы. Прежний ID `1e766e17…` утрачен; на откат
  сервера это не влияет. [Л]
- **`restart(n, broken=True)` при `image`/`capped` после `dispose`.** Воркер
  сам зовёт `repair` и знает итог. Задача пробуждения с `broken=True` только
  гасит место и кончается неудачей `config`, без `start`. Повторных `dispose`
  нет, счётчик `image_config` растёт на 1 за случай. Полный перезапуск дал бы
  второй `repair` и второй счёт. После `quarantined` — один перезапуск: файл
  унесён до `start`. [Л]
- **`StoreError` после переноса — `quarantined`** (доводка р1, Ruling 3). Файл
  уже в карантине, строка агента не обновлена. Место перезапускается и
  поднимается. Флаг сбоя учёта воркера, строка журнала `result=moved
  error=StoreError`; метка предела остаётся. `DirUnavailable` (файл не
  перенесён) — `image`, метка предела снимается. [Л]

## Б2 — «Мои агенты»: ручка шлюза и `edge`

Всё ниже — двойники `core` и разбор шаблона `edge`, **не на сервере**.

- **`GET /pcbk/api/agents`** (`test_gw_agents_api`). Сначала встроенные
  `pomoshnik` и `konstruktor` — `ready`. Затем свои агенты места в порядке
  записи: `visible` → `ready`, `saved` → `pending`, `not_visible` и
  `quarantined` → `broken`, `archived` не показывается. `own` — живые строки
  учёта, `limit` — 20. Место — только из учётки сессии: `?place=` и заголовок
  места не действуют, чужое место не видно. [Л]
- **Отказы.** Без сессии — 401. Преподаватель — 403 с текстом Д7-R64, учёт
  не читается. Вне `pcbk-front` — 404 раньше сессии и ошибки настройки. При
  `config_error` — 503 и без сессии (m24). Сбой учёта — 503 `store` (m11).
  Прочие методы — 404 без `Allow`. [Л]
- **Названия встроенных агентов** совпадают с `description` файлов образа и с
  `BUILTIN_AGENT_TITLES` веба. В копии без `web/` сверка с вебом пропускается. [Л]
- **`edge`.** `location = /pcbk/api/agents` — копия `location =
  /pcbk/api/workplace`: тела совпадают без комментариев. Путь — в полном
  списке `proxy_pass`. [Л]
- **Мутации охранных веток.** В `core` убиты 22 из 22, в шаблоне `edge` —
  6 из 6. [Л]

### Известные ограничения (Б2, записи без кода)

- **m12. `own` против предела `save`.** `own` считает только живые строки
  учёта места, `quarantined` тоже. Предел `MAX_AGENTS` у `save` считает строки
  и файлы `**/*.md` каталога места вместе. Файлы без строки бывают после
  учения или ручной правки. Тогда `own` меньше, чем считает `save`, и отказ
  `too_many_agents` приходит раньше `own == limit`. Веб `own` и `limit`
  проверяет, но не показывает (Д7-R65): расхождение видно только в ответе
  ручки и в отказе Конструктора.

## Б3 — веб: панель «Агенты» и агент разговора

### Известные ограничения (ревью Б3, записи без кода)

- **m4. Конец хода при переходе.** Переход из разговора, где идёт ход, в
  другой для чата — конец хода: `isRunning` открытого разговора гаснет, и
  список агентов перечитывается через 1 с. С итоговой доводкой (m-2) это
  намеренно: смена разговора и конец хода в оставленном разговоре тоже
  перечитывают список — лишний запрос, не больше.
- **m6. Выбор панели не сбрасывается.** Агент, выбранный в панели, ушёл из
  `ready` (архив, «не загрузился») — «Новый разговор» всё равно шлёт его
  имя. Шлюз отвечает 400 «Агент «…» недоступен» строкой над полем ввода.
  Подмены на помощника нет намеренно: агента вне списка веб не подменяет
  (Д7-R65).
- **m7. Новый разговор после Конструктора.** Разговор Конструктора открыт
  из списка, затем «Новый разговор» — агент нового разговора — последний
  выбор в панели (по умолчанию помощник), а не Конструктор: «Новый
  разговор» сохраняет выбор панели, а не агента открытого разговора
  (Д7-R65).

### Известные ограничения (Б4, записи без кода)

- **Файл агента с битым YAML — агент без своих правил.** Так ведёт себя
  OpenCode 1.18.33 с gray-matter 4.0.3. gray-matter кладёт текст в кэш до
  разбора. Повторный разбор того же текста (запасной путь `sanitize`
  OpenCode, следующая загрузка) отдаёт из кэша пустой frontmatter без
  ошибки. Итог: файл, чей frontmatter не разбирается, место загружает как
  агента: `mode: all`, `native: false`, без описания, инструкция — весь
  текст файла, правила — умолчания OpenCode `"*": allow` и глобальные
  правила образа. Ходу доступны `bash`, `edit`, `write`, `glob`, `grep`.
  Шлюз такой ход пропускает: 204, `mode` `all`. Если `sanitize` текст
  меняет, первая загрузка файл пропускает, а вторая (следующий `dispose`)
  уже загружает. Проверено живьём, диагностикой Б4 вне набора. Служба
  такой файл не пишет: шаблон v1 сверен с gray-matter на 3 896 файлах (А2).
  В место каталог смонтирован только для чтения. Путь — только ручная
  правка администратора. Карантин А6 этот случай не ловит: ошибки
  конфигурации нет. Утверждение предпроверки «битый YAML пропускается
  молча» верно только для первой загрузки текста, который `sanitize`
  меняет. **Закрыто итоговой доводкой (I-1):** правила стенда начинаются
  с `"*": "deny"` — такому агенту остаётся только чтение, шлюз его в ход
  не пускает (`mode: all`), строка учёта остаётся `not_visible`.
- **Строка вызова сохранения.** На ходе Конструктора чат пишет «Запрос к
  данным: pcbk_save_agent — готово». В `TOOL_LABELS` нет названия для
  `pcbk_save_agent`, и студент видит системное имя инструмента, хотя самому
  Конструктору такие слова запрещены (R63). **Закрыто итоговой доводкой:**
  «Запрос к данным: сохранение агента — …».
- **Панель при длинном списке разговоров.** У `.agents` `max-height: 60%`
  и `flex-shrink`. В полном прогоне у `web-a` около десятка разговоров
  тестов Д6, и панель сжимается примерно до 200 px со своей прокруткой:
  «Мои агенты» и подпись «Пока нет…» уходят за край. Выбор работает
  (кнопка прокручивается в вид), но новый агент студенту сразу не виден.
  **Закрыто итоговой доводкой:** панель не сжимается, сжимается и
  прокручивается список разговоров.
- **Снимки 02–04.** Баннер «Сбой: Историан БДРВ»: историан тестового
  стенда недостижим. Ответ агента — `unavailable` службы данных: тегов и
  чисел на снимках нет.

## Итоговая доводка Д7б

Всё ниже — двойники `core`, тесты веба (jsdom), образ места без
компоновки и локальный тестовый стенд (`pcbk-test`, настоящий Chrome),
**не на сервере**.

- **I-1. Агент без своих правил — только чтение** (находка Б4; класс шире:
  любой файл агента без `permission`). Защита в глубину:
  - **Образ.** В `student/config/opencode.json` первый ключ `permission` —
    `"*": "deny"`. OpenCode решает по последнему совпадению и порядок ключей
    сохраняет (`propertyOrder: "original"`). `read` ниже снова разрешает
    чтение. Агенты образа и шаблона службы несут свои `"*": deny` и `allow`
    позже — их наборы инструментов прежние. `GET /config` отдаёт ключи в
    порядке схемы (`read` первым), поэтому порядок проверяется по правилам
    агента (`GET /agent`): последнее правило «всё» — запрет, `read` — после
    него. [Л]
  - **Тест образа** (`test_external_read_refused_without_asking`).
    - Пробный агент без своих правил: в запросе к модели ровно `read`
      (MCP двойника отвечает 404), чтение `/proc/self/environ` — отказ по
      правилу.
    - Файл с битым YAML (`---\ndescription: "x\n---\nx\n`) в точке
      монтирования агентов: место показывает агента `mode: all` без
      описания, у его хода — тоже только `read`.
    - Отрицательный контроль (конфигурация без `permission`): в запросе
      `bash` и `edit`.
    - Мутант «без `"*": "deny"`» — красный: на сверке правил, на порядке
      правил агента и, с ожиданиями конфигурации, подогнанными под мутанта,
      на списке инструментов (`bash`, `edit`, `write`, `todowrite`,
      `skill`…). [Л]
  - **Шлюз — поправка Д5-R33.** В ход — только агенты `mode: primary`
    (`AGENT_MODES`); `mode: all` — 400 «Агент «…» недоступен». Агенты
    образа и шаблона службы — `primary`. [Л]
  - **Перезагрузка.** Видимым шаг г считает только агента `mode: primary`
    с непустым описанием (`own_agent_loaded`). Иначе строка `not_visible`,
    в панели «не загрузился», повторов `GET /agent` нет. Файл, испорченный
    мимо службы, после `reload` администратора — `not_visible`, исправленный
    — снова `visible`. Мутанты (без проверки `mode`, без описания, без
