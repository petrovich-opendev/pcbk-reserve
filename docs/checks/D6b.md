## Задача Б4. `edge`, компоновка, автотесты в браузере и учения

- **`edge`.** Зона `pcbk_web` — 1 r/s по той же карте cookie сессии, что у
  `/pcbk/api/oc/` (без cookie — общая корзина «-»), не по IP: весь класс
  бывает за одним адресом. `location = /pcbk/api/web/report`: запас 10,
  тело до 1 КиБ, срок 10 с, сырой путь сверяется, как у прочих путей шлюза.
  Отказ предела — `509` → `busy.json` (503 `WorkplaceBusy`), как у всех
  пределов Д5б, а не 429 из брифа (решение контролёра, Н2): 429 у `edge` —
  «Слишком много попыток входа». `location = /chat/boot.js` — загрузчик без
  хеша: CSP R41, `no-store`, `nosniff`, `no-referrer` (своё `add_header`
  отменяет заголовки `server` — повторены все), `charset utf-8` (в
  загрузчике русский текст сбоя). JS-тест шаблона сверяет путь в полном
  списке `proxy_pass` и тело обеих `location` (Ф6). [Л]
- **Живой `edge` тестового стенда** (`test_edge`): отчёт без сессии — 401
  JSON шлюза; тело 2 КиБ — 413 JSON `edge`, до `core` не доходит;
  `/pcbk/api/web/other` — 404 JSON; `/pcbk/api/web//report` — 400; 20
  отчётов подряд без cookie — 401 и 503 `WorkplaceBusy`, 429 нет.
  `/chat/boot.js` — 200, `application/javascript; charset=utf-8`, без
  сжатия, CSP R41 и `no-store`; сумма тела совпадает с описью `build.json`. [Л]
- **Предупреждение при первом входе** (`test_first_login_notice`, вкладка со
  своими cookie — Ф3). Вход формой ведёт в `/chat/` на экран предупреждения;
  до «Понятно» ни одного `POST /pcbk/api/workplace*` и ни одного запроса под
  `/pcbk/api/oc/`, в `accounts list` — «нет». «Понятно» —
  `POST /pcbk/api/auth/notice` через `edge` и шлюз (204), затем место и поле
  чата, в `accounts list` — «да». Нарушений CSP и ошибок консоли — 0. [Л]
- **Прочие тесты модуля** подтверждают предупреждение мимо шлюза —
  `ensure_notice_acked` (Ф5): `ack_notice` тем же `AccountStore` в `pcbk-core`,
  без пароля и без новой сессии (вход вытеснил бы сессию вкладок), после —
  сверка столбца «предупреждён» целиком (Н3). `test_web` Д6а снова зелёный. [Л]
- **Список разговоров** (`test_rename_and_archive_through_gateway`).
  Самозаголовок OpenCode доходит до строки `[data-session-id=…]` без
  перезагрузки (Ф13). «Переименовать» в строке по id → имя в месте (мимо
  шлюза) — «Проверка Д6б»; «В архив» → `time.archived` в месте, строка ушла;
  отказов шлюза (`refused_1h`) не прибавилось. [Л]
- **Четвёртая вкладка** (`test_fourth_tab_told_to_close`). Три вкладки
  открыли тот же разговор и получили поток (200 до следующей вкладки), у
  четвёртой — «Открыто слишком много вкладок чата — закройте лишние», у трёх
  первых этой строки нет. Закрыли вторую — следующая попытка четвёртой по
  паузе получила поток, строка ушла. Вкладки сверх фикстуры закрываются в
  `finally` (Ф4). [Л]
- **Отчёты в строке** (`test_reports_reach_row`, последним в модуле). До
  отчёта `/health/web` — четыре нуля: ложных отчётов за модуль нет (то же
  ловит точная тройка `ok` учения строки). `fetch` страницы чата →
  `POST /pcbk/api/web/report` `turn_silent` — 204, счётчик 1, строка «Веб-чат»
  — `warn` «ответ модели не пришёл вовремя», «1 за час». [Л]
- **Живая проверка m3 ревью Б3 — часть `retry` на попытку модели**
  (`test_model_retries_recorded`, двойник OpenRouter: `FAKE500` → прокси 502
  → OpenCode повторяет). Место 1.18.33 повтор показывает **только статусом
  разговора** (`session/status`: `retry` с номером попытки, между
  попытками — `busy`); **частей у ответа нет ни одной** — ни `retry`, ни
  других; сообщение ответа есть, пустое. Два прогона: 3 попытки за 7,8 и
  9,9 с, затем «Стоп»; сколько попыток без «Стопа», не мерили. Вывод (по
  коду `watch.ts`, 180 с живьём не ждали): отпечаток хода во время повторов
  стоит, и ход из одних повторов дольше 180 с `turn_silent` даёт —
  молчание не маскируется.
  Комментарий в `watch.ts` о частях `retry` как приросте к 1.18.33 не
  относится — правка в итоговой доводке. Тест закрепляет это поведение:
  место, начавшее писать части `retry`, его уронит. Отчётов браузера за ход с
  повторами — 0. Третий прогон (полный): статус `retry` с попытками 1, 2, 3,
  частей 0. Побочный след: три ошибки модели подряд дают строке «LLM-прокси
  и бюджет» `warn` «OpenRouter отвечает ошибками подряд» на один такт
  сторожа — баннер студента `warn` этой строки не показывает (доводка Д6а,
  P1). [Л]
