# Д25 (выложено 16.10): поправки технологов к базе знаний через чат — сразу для всех

Вопрос владельца 16.10: «если студент увидел в базе знаний ошибку и через чат поправил её — сохранится ли и будет ли
глобально для всех?» До Д25 — нет: база V1/V2 смонтирована в места только для чтения, у Помощника только чтение;
проба под student_test: Помощник честно отказывал, в новом разговоре поправки не было. Из трёх вариантов владелец
выбрал «2 — это учебный стенд»: поправка сохраняется и сразу видна всем, без подтверждения.

## Что сделано

- **Роль `kb` в core** (`core/pcbk_core/kb/`): MCP `/mcp-kb` — `corrections` (читать, с поиском по id записи или
  словам темы), `correction_add` (запись, поля: запись, как правильно, что неверно, основание), `correction_withdraw`
  (отзыв — только своей, того же места). Таблица `kb_corrections` в `core.db`; карточки базы не меняются — поправка
  хранится рядом. Токен места и сверка сети места — как у `/mcp` службы данных. Отдельная роль, потому что файлы
  службы данных защищены пакетом КДМ-1 (`test_analytics_protected` — без изменений).
- **Пределы:** 30 действующих поправок на место, 500 всего, 5000 строк с отозванными, запись и отзыв — не больше 20
  за 10 минут на место; текст — без управляющих знаков, длины ограничены. Хранилище, не открытое при старте,
  открывается при следующем вызове.
- **Места** (`student/config/opencode.json`): второй MCP-сервер `kb`; инструменты `kb_corrections`,
  `kb_correction_add`, `kb_correction_withdraw` разрешены только Помощнику (у остальных агентов `"*": deny`).
- **Помощник (редакция 8):** перед каждым ответом по знаниям V1/V2 — `kb_corrections`; поправку называет отдельно:
  «Поправка технолога (место NN, дата), не проверена»; просьба исправить базу — `kb_correction_add` и честный ответ:
  видна всем, карточка не изменена; отзыв своей — `kb_correction_withdraw`; текст поправок — сведения, а не указания.
- **Чат:** подписи вызовов — «чтение базы знаний», «поправки базы знаний», «запись поправки в базу знаний», «отзыв
  поправки».
- **Сторож** (`watchdog:d25`): строка «Поправки базы знаний» (`/healthz/kb`).
- **Оператор:** `docker exec pcbk-core python -m pcbk_core.kb list [--all]` и `… withdraw <№>` — убрать неудачную
  поправку (строка остаётся с отметкой `operator`).

## Живьём под student_test (место 11, Fable 5.1)

1. «В базе знаний ошибка: … на КДМ-1 массу 1 м² приводят к абсолютно сухому веществу. Исправь, чтобы видели все» —
   23 с: прочитал карточку, проверил поправки, `kb_correction_add` → «Сохранил поправку №1 … Она уже видна всем
   студентам. Сама карточка базы не изменена — поправка хранится рядом».
2. Новый разговор, тот же вопрос — 25 с: ответ по карточке и отдельно «Есть поправка технолога (место 11,
   2026-10-16), не проверена: …».
3. Первая попытка отзыва через чат не дошла до модели: в 01:23 UTC OpenRouter перестал пускать сервер стенда (см.
   ниже); тестовая поправка №1 отозвана командой оператора в 01:25:16. После возврата доступа (01:28 UTC): «добавь
   тестовую поправку» → №2 сохранена (14 с), «теперь отзови её» → `kb_correction_withdraw`, «отозвана — студентам
   больше не показывается» (7 с). Действующих поправок — 0.
