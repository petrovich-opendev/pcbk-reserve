## Что сделано

- `LLM_FALLBACK=<основная>=<запасная>[,…]` (`core/pcbk_core/llm/settings.py`, `parse_fallback`): имена — точные имена
  кандидатов, запасная — из `LLM_MODELS`, ошибка — ошибка настройки LLM-прокси.
- `core/pcbk_core/llm/api.py`, `_attempt_fallback`: при отказе основной модели вида «подождите/недоступен» (`wait`,
  `down`) до первого байта ответа — один повтор того же запроса на запасной модели. Резерв основной снимается, доля места
  и бюджет проверяются заново. Место (OpenCode) первого отказа не видит.
- Строка журнала `core`: `llm … model=<запасная> … fallback_from=<основная> fallback_reason=<вид отказа>`; в
  `llm_calls` — две строки (отказ основной и ответ запасной).
- Тесты: `core/tests/test_llm_fallback.py` (разбор `LLM_FALLBACK`, повтор на двойнике OpenRouter), правки
  `test_skeleton.py`, `test_llm_role.py`, `tests/integration/test_edge.py` (состав переменных `pcbk-core`).
- Образ `core:d14a`; README «Модели по ролям» — абзац «Запасная модель».
