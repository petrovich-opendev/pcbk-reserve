# Расчёты

Шесть инструментов службы данных считают производные показатели поверх ряда историана, а не отдают его как
есть: `calc_runtime` (наработка по тегам состояний), `calc_deviation` (отклонение измерения от задания),
`equipment` (подсчёт агрегатов каталога), `calc_spc` (карта Шухарта и SPC), `calc_flow_total` (суммарный
расход за период) и `calc_formula` (расчёт по формуле над рядами тегов). Все шесть — методы `DataService` в
`core/pcbk_core/data/service.py`; арифметика, не зависящая от историана и каталога, вынесена в отдельные
модули без ввода-вывода: `core/pcbk_core/spc.py` (SPC), `core/pcbk_core/flow.py` (интеграл расхода),
`core/pcbk_core/formula.py` (разбор и счёт формулы). Про саму службу данных, её ворота, каталог, кэш, периоды
и формат событий — в [службе данных](10-data-service.md); здесь — только расчётная часть.

Отдельно описана вкладка «Калькуляторы» веб-чата: не все шесть инструментов ей доступны (раздел
[«Вкладка «Калькуляторы»»](#вкладка-калькуляторы)).

## Общее у всех расчётов

- Вызов — метод `DataService` вида `calc_*(caller, channel, …)`; `caller` — id вызывающего (место студента,
  `teacher` или служебный), `channel` — `"http"`, `"mcp"` или `"web"`. Ответ — всегда `dict` с полями `tool`
  (имя инструмента) и `status`.
- `status` — одно из `ok`, `partial`, `refused`, `budget`, `rate`, `busy`, `timeout`, `unavailable`, `error`
  (`Outcome`, `core/pcbk_core/data/events.py`). Отказ до похода в историан (`refused`, `budget`, `rate`) не
  шлёт SQL; ответ отказа — `{"tool", "status", "message", "notes": [], "cache", …}` (сообщение для человека и
  доп. поля отказа, например `items` у «ни один тег нельзя запросить» или `period`/`cost_tag_days` у
  `budget`). Общие тексты сообщений — `MESSAGES` в `service.py` (например `MESSAGES["none"]` = «ни один тег
  нельзя запросить», `MESSAGES["args"]` = «неверные аргументы: » перед текстом конкретной причины).
- `calc_deviation`, `calc_spc`, `calc_flow_total`, `calc_formula` читают ряд тем же путём, что `tag_series`:
  белый список каталога (только аналоговые теги) → бюджет тего-суток → бюджет точек (теги × points ≤
  288) → кэш/single-flight → ворота → SQL историана (порядок шагов инструмента — общий, из `service.py`:
  каталог → период и бюджет → кэш → single-flight → ворота). Ключ кэша и имя TTL-профиля на этом шаге у всех четырёх —
  буквально строка `"tag_series"` (`cache_key("tag_series", …)`, `ttl_for("tag_series", …)`), не имя самого
  инструмента: если, например, `tag_series` и `calc_spc` запрошены с тем же набором тегов, тем же периодом и
  тем же числом точек, они делят одну запись кэша службы. Событие вызова и поле `tool` ответа при этом — свои
  у каждого инструмента (`calc_spc`, `calc_flow_total`…), не `tag_series`. Только `calc_runtime` читает своим, отдельным
  путём — `StateSummaryHistory` (`state_sql`) — своей записью кэша с ключом `"calc_runtime"`; это не общий
  путь `tag_series`, как и у `tag_period` тоже свой отдельный путь, но через ДРУГУЮ таблицу историана —
  `AnalogSummaryHistory` (`summary_sql`; подробнее — в [службе данных](10-data-service.md)).
- Период — готовый (`period`, один из `PRESETS`: `last_hour`, `last_8h`, `last_24h`, `current_shift`,
  `prev_shift`, `today`, `yesterday`, `last_7d`, `last_30d`) или свой (`start`/`end`, ISO 8601); нельзя
  одновременно. Окно — не длиннее 31 суток; тего-сутки (теги × длина окна, минимум 1 час) — не больше 24 для
  нескольких тегов, 31 для одного. Подробности периодов, смен и бюджета — в
  [службе данных](10-data-service.md).
- Годная точка ряда — значение есть (не `NULL`) и качество хорошее (`Quality = 0`); иное — пропускается, не
  приравнивается к нулю.
- `notes` — список замечаний для текста ответа (например `SHIFT_NOTE` про смены КДМ-1, `OPEN_NOTE` — период
  ещё идёт, `GRID_NOTE` — сетка равномерная, всплески короче шага не видны).

## `calc_runtime` — наработка по тегам состояний

Назначение: часы, доля периода и число переходов в каждом состоянии тега — по сырым данным историана
(`StateSummaryHistory`), не по равномерной сетке.

**Вход** (`DataService.calc_runtime`, HTTP `/api/data/calc_runtime`, MCP `calc_runtime`):

| Аргумент | Тип | Предел | По умолчанию |
|---|---|---|---|
| `tags` | список строк | 1–16 тегов (`MAX_NAMES`), каждый ≤ 128 знаков | — |
| `period` | строка | один из `PRESETS` | — |
| `start`, `end` | строка ISO 8601 | — | — |

Только теги вида `discrete` (состояние) идут в SQL; аналоговый тег в списке получает в ответе статус
`"analog"` с текстом «аналоговый тег: наработка считается только по тегам состояний — сводку даёт
`tag_period`» (`ITEM_TEXTS["analog"]`), тег вне белого списка — `"unlisted"`, неизвестный — `"unknown"`. Если
среди тегов нет ни одного состояния — отказ `refused` с `MESSAGES["none"]`, SQL не уходит.

**Алгоритм** (`DataService._runtime_item`): строки `StateSummaryHistory` дают по каждому значению состояния
`(value, StateTimeTotal мс, PercentOfTime, StateCount)`. Часы = `StateTimeTotal / 3_600_000`
(`MS_PER_HOUR`). Строка-«шум» (значение `None` и часы `NULL`/`0`, т. е. состояние не встретилось) отбрасывается
(`_state_noise`). Состояния со значением сортируются по убыванию числа; «нет данных» (`value is None`, часы и
доля есть) — последней строкой с подписью `NO_DATA_LABEL` = «нет данных». Подпись состояния по значению —
`STATE_LABELS` в `service.py` по суффиксу имени тега: `_RUN` → «работает»/«стоит», `_OPN` →
«открыт»/«не открыт», `_CLS` → «закрыт»/«не закрыт», `_ON`/`_OFF`, `_STOP`, `_FLT` → «неисправность»/«исправен»,
`_ALM` → «авария»/«нет аварии»; суффикс без подписи — `state_label` не ставится (значение всё равно есть).
`covered_percent` — сумма `percent` состояний со значением; если хотя бы у одного состояния часы не нулевые, а
доли нет (`PercentOfTime IS NULL`) — `covered_percent` = `null` без `coverage_note` (данные есть, но доля
историаном не посчитана — служба не утверждает «0 %»). Если `covered_percent` посчитан и меньше
`COVERAGE_MIN` = 99,0 — добавляется `coverage_note` = «данные покрывают `N` % периода — часы состояний в
сумме меньше периода».

**Ответ** (пример, вымышленный тег `25FAKE_007_CLS` — клапан, смена `yesterday` = 24 ч):

```json
{
  "tool": "calc_runtime", "status": "ok", "notes": [],
  "period": {"start": "2026-09-30T00:00:00+05:00", "end": "2026-10-01T00:00:00+05:00",
             "preset": "yesterday", "tz": "+05:00", "shift_grid_assumed": false, "clamped": false, "open": false},
  "source": "время в каждом состоянии по сырым данным историана (StateSummaryHistory)",
  "cost_tag_days": 1.0, "cache": "miss",
  "items": [
    {"tag": "25FAKE_007_CLS", "status": "ok", "description": "Клапан подачи закрыт",
     "states": [
       {"value": 1, "label": "закрыт (по суффиксу)", "hours": 18.0, "percent": 75.0, "count": 3},
       {"value": 0, "label": "не закрыт (по суффиксу)", "hours": 6.0, "percent": 25.0, "count": 3}
     ],
     "covered_percent": 100.0, "period_hours": 24.0}
  ]
}
```

**Отказы**: `tags` не список/пусто/>16/не строки/длиннее 128 — `refused`, текст из `_tags_problem` (например
«tags: не больше 16 тегов за вызов»). Нет ни одного тега-состояния в списке (все аналоговые/вне
списка/неизвестные) — `refused`, `MESSAGES["none"]`, `items` — по каждому входному тегу с его статусом. Окно
длиннее 31 суток или дороже тего-суток — `budget` с текстом `check_budget` («период длиннее 31 суток» или
«запрос стоит … тего-суток при пределе 24 …»), в ответе `period` и `cost_tag_days`, но без `items`.

Переносимость: переносимый — подписи `STATE_LABELS` общие для любой МЭС с тегами состояний на тех же
суффиксах; свои для заказчика — только сами суффиксы, если на другом предприятии другая конвенция имён (их
нужно будет подвести под `AGGREGATE_TAILS`/`STATE_LABELS`, см. [21-extending.md](21-extending.md)).

## `calc_deviation` — отклонение измерения от задания регулятора

Назначение: контрольная точка «измерение против задания» считается службой, не агентом «в уме»: |измерение −
задание| по совпадающим меткам ряда и сравнение с порогом технолога.

**Вход** (HTTP `/api/data/calc_deviation`, MCP `calc_deviation`):

| Аргумент | Тип | Предел | По умолчанию |
|---|---|---|---|
| `measure_tag` | строка | ≤ 128 знаков, аналоговый тег белого списка | — |
| `setpoint_tag` | строка | то же | — |
| `threshold` | число | строго больше 0, конечное (не `bool`, не `NaN`/`inf`) — порог технолога, не норматив | — |
| `period`/`start`/`end` | как у прочих | окно ≤ 31 суток | — |
| `points` | целое | 2–96 (`SERIES_MIN_POINTS`…`SERIES_MAX_POINTS`) | 72 (`DEVIATION_DEFAULT_POINTS`) |

Оба тега читаются одним запросом ряда (как `tag_series` с `tags=[measure_tag, setpoint_tag]`, кроме случая,
когда это один и тот же тег — тогда читается один раз). Тег вне белого списка, неизвестный или дискретный у
любой из двух ролей — отказ `refused`, `MESSAGES["none"]`, до SQL (как у `tag_series`).

**Алгоритм** (`_deviation_pairs`, `_deviation_stats`, `_deviation_interval`): пары `(метка, измерение,
задание)` — только там, где у ОБОИХ тегов на этой метке сетки есть значение; пропуск у любого из двух — точка
в пару не входит (не ноль, не предыдущее значение). `over_count` — число пар, где `|измерение − задание| >
threshold` (строго). `max_abs_dev`/`mean_abs_dev` — по всем парам. `intervals` — подряд идущие пары сверх
порога, каждая — `{"start", "end", "points", "max_abs_dev", "at", "value", "setpoint"}`, где `at`/`value`/
`setpoint` — точка интервала с наибольшим отклонением (первая из равных).

**Ответ** (пример: `20FAKE_001_PV` — измерение, `20FAKE_002_SP` — задание, порог 2.0):

```json
{
  "tool": "calc_deviation", "status": "ok", "measure_tag": "20FAKE_001_PV", "setpoint_tag": "20FAKE_002_SP",
  "threshold": 2.0, "points": 4, "max_abs_dev": 11.0, "mean_abs_dev": 5.375, "over_count": 2,
  "intervals": [
    {"start": "2026-10-01T06:00:00+05:00", "end": "2026-10-01T08:00:00+05:00", "points": 2,
     "max_abs_dev": 11.0, "at": "2026-10-01T08:00:00+05:00", "value": 21.0, "setpoint": 10.0}
  ],
  "notes": ["сетка равномерная: всплески короче шага не видны — истинные минимум, максимум и среднее даёт tag_period"],
  "cache": "miss",
  "period": {"start": "2026-10-01T04:00:00+05:00", "end": "2026-10-01T12:00:00+05:00", "preset": null,
             "tz": "+05:00", "shift_grid_assumed": false, "clamped": false, "open": false}
}
```

`status` — `"partial"`, если у измерения или задания в периоде не нашлось вообще ни одного значения (но ряд
читался); тогда в `notes` добавляется `"<tег>: за период данных нет"`.

**Отказы**: `measure_tag`/`setpoint_tag` не строка или длиннее 128 — `refused` («measure_tag: нужен тег
строкой», «setpoint_tag: строка тега длиннее 128 знаков»). `threshold` ≤ 0, не число, `bool`, `NaN`/`inf` —
«threshold: число больше 0». `points` вне 2–96 — «points: от 2 до 96». Любой тег вне белого списка, неизвестен
или не аналоговый — `MESSAGES["none"]`, без SQL.

Переносимость: полностью переносимый расчёт (регулятор `_PV`/`_SP` — общее понятие контура регулирования, не
специфика КДМ-1); специфичного для заказчика в этом инструменте нет, кроме самих имён тегов на входе.

## `equipment` — подсчёт агрегатов каталога

Назначение: «сколько насосов/задвижек/мешалок…» и «сколько сейчас в работе» — служба сама группирует теги
белого списка в агрегаты по словам запроса, не агент.

**Вход** (MCP-инструмент без HTTP-ручки; `EquipmentArgs` в `mcp_server.py`):

| Аргумент | Тип | Предел | По умолчанию |
|---|---|---|---|
| `query` | строка | 1–200 знаков (`QUERY_CHARS`) | — |
| `with_state` | bool | — | `false` |

**Алгоритм группировки** (`Catalog.equipment`, `core/pcbk_core/data/catalog.py`): у каждого тега белого
списка имя разбирается на основу и хвост (`_split_tail`, всё после последнего `_`). Основы с общим именем
группируются; основа, у которой есть хотя бы один тег с хвостом из `AGGREGATE_TAILS` = `{RUN, LOD, SPD, CUR,
OP, OPN, CLS, ON, OFF, STOP, FLT, ALM}`, — агрегат; основа без такого хвоста — точка измерения (считается
отдельно в `measure_points_total`, не входит ни в `units`, ни в `mentions`). Основа подходит запросу, если все
слова запроса (`norm`: нижний регистр, «ё»→«е», пробелы схлопнуты) есть в имени или описании хотя бы одного её
тега. Из подходящих агрегатов: если первое слово запроса входит подстрокой в одно из первых двух слов описания
(`_is_head`, `HEAD_WORDS` = 2) хотя бы у одного тега основы — это `Unit` (считается в
`units_total`/`groups`/`with_state`); если слово есть в описании, но не в начале, — это `Mention`
(отдельно в `mentions`, не входит в `units_total` и не читает состояние). Группа агрегата (`group`) —
ведущие цифры кода, иначе префикс до первого `_`, иначе код целиком (`_group_of`).

**Ответ без `with_state`** (SQL не уходит — как `catalog_search`, каталог целиком в памяти): пример на запрос
«клапан» с одним подходящим агрегатом `25FAKE_007` (хвост `_CLS`):

```json
{
  "tool": "equipment", "status": "ok", "query": "клапан",
  "units_total": 1, "tags_total": 1, "measure_points_total": 0, "truncated": false,
  "units": [{"code": "25FAKE_007", "description": "Клапан подачи закрыт", "signals": ["CLS"], "group": "25"}],
  "groups": {"25": 1}, "mentions_total": 0, "mentions": [],
  "notes": ["агрегат здесь — основа имени тега (без хвоста), у которой есть тег привода или состояния: RUN, LOD, SPD, CUR, OP, OPN, CLS, ON, OFF, STOP, FLT, ALM",
            "коды с одинаковым описанием бывают одним механизмом — не считайте их разными агрегатами не глядя",
            "весь каталог стенда — участок КДМ-1"],
  "cache": "none"
}
```

`units` — полный список подходящих агрегатов (с словом запроса в начале), но не больше `EQUIPMENT_UNITS_CAP`
= 300 на вывод; `units_total`/`tags_total`/`groups`/`measure_points_total` — по всем подходящим, без обрезки.
Обрезка ставит `truncated: true` и заметку «показаны первые 300 из `N`…». `mentions` — до
`EQUIPMENT_MENTIONS_CAP` = 100, `mentions_total` — полный счёт; когда он больше нуля, добавляется заметка
`EQUIPMENT_MENTION_NOTE` («число — оборудование, в начале названия которого есть слово запроса; ещё `N`
единиц оборудования упоминают его в описании…»).

**С `with_state=true`**: дополнительно читает текущее значение тега `_RUN` каждого агрегата из `units` (не
`mentions`) тем же путём, что `tag_now` (пачками по `MAX_NAMES` = 16, один счёт частоты на весь вызов). У
агрегатов больше `EQUIPMENT_RUN_CAP` = 120 с тегом `_RUN` — отказ `refused`,
`EQUIPMENT_RUN_LIMIT_MESSAGE` = «агрегатов с тегом \_RUN больше 120 — сузьте запрос», до SQL. Каждый элемент
`units` получает `state` — одно из `EQUIPMENT_STATES` = `("running", "stopped", "no_data", "no_run_tag")`,
`time` (ISO) и `item_notes` (например `EQUIPMENT_STALE_NOTE` = «значение не менялось больше суток», порог
`EQUIPMENT_STALE_S` = 86400 с — свой, не 10-минутный порог `tag_now`: агрегат сутками «в работе» — это не
залипание). Ответ получает `state_counts` — число агрегатов в каждом состоянии.

**Отказы**: `query` не строка, пустая или длиннее 200 — «query: нужна строка от 1 до 200 знаков».
`with_state` не `bool` — «with\_state: нужен bool». Нет ни одного подходящего агрегата/точки — `status: "ok"`
с нулями (это не отказ, запрос мог быть неудачным по формулировке, не по аргументам).

Переносимость: алгоритм группировки и хвосты `AGGREGATE_TAILS` — общее соглашение об именах тегов
(привод/состояние суффиксом), годится для любой МЭС с такой конвенцией; специфично для заказчика — только
содержимое каталога (имена и описания тегов КДМ-1) и число 300/100/120 как пределы вывода, которые можно
менять без переноса алгоритма.

## `calc_spc` — карта Шухарта и SPC

Назначение: карта Шухарта (I-MR или X̄-R), 8 правил Нельсона, Cp/Cpk/Pp/Ppk и мини-график — считает служба
(`core/pcbk_core/spc.py`), не модель.

**Вход** (MCP-инструмент без HTTP-ручки; `CalcSpcArgs`):

| Аргумент | Тип | Предел | По умолчанию |
|---|---|---|---|
| `tag` | строка | ≤ 128 знаков, один аналоговый тег белого списка | — |
| `period`/`start`/`end` | как у прочих | окно ≤ 31 суток | — |
| `points` | целое | 20–96 (`SPC_MIN_POINTS`…`SERIES_MAX_POINTS`) — выше нижней границы `tag_series`: карта короче статистически не читается | 96 (`SPC_DEFAULT_POINTS`) |
| `subgroup` | целое | 1–10 (`SPC_MAX_SUBGROUP`): 1 — I-MR, 2–10 — X̄-R | 1 |
| `lsl`, `usl` | число | конечное, не `bool`; если заданы оба — `usl` строго больше `lsl` | `null` (без допуска) |

Читает ряд тем же путём, что `tag_series`/`calc_deviation`. Дискретный, неизвестный или вне списка тег —
отказ `MESSAGES["none"]` до SQL.

**Обработка качества данных** (`_spc_valid_points`): пустая точка ИЛИ недостоверное качество (`Quality ≠ 0`)
пропускается до расчёта, не идёт в карту; их число — поле ответа `skipped`, не молча. Если валидных точек
после пропуска меньше, чем нужно для хотя бы одной точки карты (2 для I-MR, `subgroup` для X̄-R) — это не
падение: `status: "partial"`, SQL уже ушёл (данные читались), но `cl`/`ucl`/`lcl`/`secondary`/`capability` —
`null`, `violations: []`, `sparkline: ["", ""]`, `plot: null`, в `notes` — `SPC_NOT_ENOUGH_NOTE` = «после
пропуска пустых и недостоверных точек ряда данных недостаточно для карты».

**Алгоритм** (`core/pcbk_core/spc.py`, чистые функции без ввода-вывода):

- **I-MR** (`subgroup=1`, `individuals()`): `CL` = среднее валидных значений; `MR_i = |x_i − x_{i−1}|` по
  соседним точкам; `MR̄` — среднее скользящих размахов; `σ̂ = MR̄ / 1.128`; `UCL/LCL = CL ± 2.66·MR̄`.
  Вторичная карта размахов (`secondary`): `CL_MR = MR̄`, `UCL_MR = 3.267·MR̄`, `LCL_MR = 0`. Точка карты — само
  значение, `sigma_point = σ̂`.
- **X̄-R** (`subgroup = n`, 2–10, `xbar_r()`): валидные точки режутся на подгруппы по `n` подряд; хвост короче
  `n` отбрасывается (число — в заметке «`N` точек в конце ряда не вошли в подгруппу (хвост короче `n`)», поле
  ответа `discarded` внутри модуля). `X̿` — среднее средних подгрупп, `R̄` — среднее размахов (max−min
  подгруппы); константы `A2, D3, D4, d2` по таблице ASTM/AIAG (`_CONSTANTS`, n=2..10, например n=4: A2=0.729,
  D3=0, D4=2.282, d2=2.059); `UCL/LCL = X̿ ± A2·R̄`; вторичная карта (`secondary`): `CL_R = R̄`, `UCL_R =
  D4·R̄`, `LCL_R = D3·R̄`; `σ̂ = R̄/d2`; точка карты X̄ имеет `sigma_point = σ̂/√n`. Время точки карты —
  время последней точки подгруппы.
- **Правила Нельсона** (`rules()`, список из 8, `_RULE_NAMES_RU`): 1 — точка за 3σ; 2 — 9 подряд по одну
  сторону CL; 3 — 6 подряд монотонно растут/падают; 4 — 14 подряд попеременно вверх-вниз; 5 — 2 из 3 подряд за
  2σ по одну сторону; 6 — 4 из 5 подряд за 1σ по одну сторону; 7 — 15 подряд в пределах 1σ; 8 — 8 подряд вне
  1σ по обе стороны (смесь). Правило на окне из нескольких точек засчитывается на последней точке окна по
  индексу, но зона (`A`/`B`/`C`/«вне»; `>3σ`/`>2σ`/`>1σ`/иначе) берётся по самой далёкой от CL точке внутри
  окна, не по последней. `σ = 0` (ряд абсолютно стабилен) — точки, равные CL, получают z=0 (зона C, правила
  2/5/6/8 по ним не срабатывают), точка, отличная от CL, — z=±∞ (зона «вне», правило 1 срабатывает). Ответ
  службы сворачивает точечные нарушения в интервалы подряд идущих точек по каждому правилу (`_spc_intervals`:
  `{"rule", "name_ru", "start", "end", "points", "value_min", "value_max"}`) — не точка за точкой: иначе при
  смене режима правило 1 может сработать на каждой из 96 точек и ответ в чате обрезается. Поле `rule_counts`
  — число точек-нарушений по каждому правилу (строкой номера), без обрезки; список интервалов — не больше
  `SPC_MAX_INTERVALS` = 40, при обрезке — заметка. `in_control` = `not violations`.
- **Capability** (`capability()`, только если задан `lsl` и/или `usl`): `Cp/Cpk` — по `sigma_within` (σ̂
  карты, внутригрупповая вариация), `Pp/Ppk` — по `sigma_overall` (выборочное СКО ряда, `n−1`). Обе границы:
  `Cp = (usl−lsl)/(6·σ_within)`, `Cpk = min(usl−μ, μ−lsl)/(3·σ_within)`, аналогично `Pp/Ppk` с `σ_overall`.
  Только одна граница — считается лишь односторонний `Cpk`/`Ppk` по ней (`Cp`/`Pp` = `null`: у одностороннего
  допуска нет ширины поля). Если все значения ряда одинаковы (`σ_overall = 0`) — `Pp/Ppk` не определены,
  `capability` остаётся `null`, в `notes` добавляется «Cp/Cpk/Pp/Ppk не посчитаны: σ\_общ (выборочное СКО)
  равна нулю — все значения ряда одинаковы, Pp/Ppk не определены». Границы допуска —
  порог технолога, НЕ норматив ПЦБК (`SPC_BOUNDS_NOTE` в ответе).
- **Sparkline** (`sparkline()`): строка 1 — точки символами `▁▂▃▄▅▆▇█` (8 уровней) от `min(LCL, min(points))`
  до `max(UCL, max(points))`; строка 2 — под точками: `▲` выше UCL, `▼` ниже LCL, `•` — иное нарушение правила
  (точка в пределах границ, но её индекс среди нарушений), пробел иначе.

**Поле `plot`** (последним в ответе — чат рисует график сам, модель числа не пересказывает):
`{"points": […], "secondary": […], "flagged": […], "lsl", "usl", "start", "end"}`. `points` — точки основной
карты, `secondary` — точки вторичной (MR — на одну короче points, с второй точки; R — по подгруппам), оба
округлены до 5 значащих цифр (`SPC_PLOT_DIGITS`, `_plot_number`: короче в ответе, на графике разницы нет).
`flagged` — индексы точек с хотя бы одним нарушением правила. `start`/`end` — время первой и последней точки
карты.

## `calc_flow_total` — суммарный расход за период

Назначение: суммарный расход (масса/объём) за период по мгновенным показаниям расходомера — интеграл методом
трапеций, не простая сумма показаний. Считает служба (`core/pcbk_core/flow.py`), не модель.

**Вход** (MCP-инструмент без HTTP-ручки; `CalcFlowArgs`):

| Аргумент | Тип | Предел | По умолчанию |
|---|---|---|---|
| `tag` | строка | ≤ 128 знаков, один аналоговый тег | — |
| `period`/`start`/`end` | как у прочих | окно ≤ 31 суток | — |
| `points` | целое | 20–96 (`FLOW_MIN_POINTS`…`SERIES_MAX_POINTS`): меньше — шаг сетки грубый, допустимый разрыв перестаёт ловить пропуски | 96 (`FLOW_DEFAULT_POINTS`) |
| `unit` | строка или `null` | ≤ 20 знаков (`FLOW_UNIT_CHARS`) — только если в каталоге у тега единицы нет | `null` |

**Единицы** (`flow.parse_unit`, `core/pcbk_core/flow.py`): единица тега разбирается на вид:
- **rate** (мгновенный расход) — вида «количество/время», числитель из `QUANTITY_UNITS` =
  `{т, кг, г, м3, нм3, л, гкал, мвт·ч, квт·ч}`, знаменатель из `TIME_UNITS` (ч/час/h/hr → 3600 с, мин/min →
  60 с, с/сек/s/sec → 1 с, сут/сутки/d → 86400 с); например «т/ч», «кг/с», «л/мин», «м3/ч».
- **counter** (накопительный счётчик) — количество без «/время» (т, кг, л, м3…): показания уже накоплены,
  повторно не интегрируются — отказ.
- **other** — прочее (°C, %, мбар, м/мин, г/м2…) — не расход, отказ.
- **unknown** — единицы нет вовсе.

Единица берётся из каталога историана, если она там вообще задана (любого вида — `rate`, `counter` или
`other`, не только `rate`; переданный `unit` в этом случае не используется вовсе, даже если он верный).
Если в каталоге единицы нет (`unknown`) — берётся переданный `unit` (должен быть распознан как `rate`,
иначе отказ); в ответ добавляется заметка `FLOW_UNIT_TECH_NOTE` = «единицы нет в каталоге историана —
взята названная технологом». Если в каталоге единица задана и отличается от переданной — берётся
КАТАЛОЖНАЯ (переданная игнорируется), с заметкой «в каталоге единица «…» — взята она, а не
названная «…»».

**Алгоритм интеграла** (`flow.integrate`): трапеции по фактическим интервалам между соседними точками сетки,
не равным долям суток — `вклад = (vₐ + v_b)/2 × (b−a)/per_s`, где `per_s` — секунд в знаменателе единицы (т/ч
→ переводит в часы, итог в т; кг/с → в секундах, итог в кг). Отрезок (a, b) входит в интеграл только если
ОБЕ точки годные (значение есть, качество хорошее) и `0 < b−a ≤ max_gap_s`; `max_gap_s` = шаг сетки периода ×
1,5 (`FLOW_GAP_STEPS`) — допуск на округление меток историана. Разрыв длиннее допустимого — не интегрируется
(`gaps` растёт), пропуск НЕ считается нулевым расходом. Края периода до первой и после последней годной точки
— непокрытые, крайнее значение на них не распространяется (без экстраполяции). Отрицательные показания —
интегрируются как есть (с заметкой, сколько их было) — служба не решает за технолога, что это ошибка.
Покрытие (`coverage_percent`) — доля длины проинтегрированных отрезков от длины периода; при полном покрытии
— 100,0 % (с допуском `COVERAGE_TOLERANCE_S` = 1 с на округление меток).

**Ответ** (пример: `20FAKE_001_PV`, 10 т/ч постоянно 3 часа, 25 точек, шаг 7,5 мин):

```json
{

  "total": 30.0, "total_unit": "л", "complete": true, "coverage_percent": 100.0,
  "unit": "л/час", "unit_source": "каталог",
  "period": {"start": "2026-10-01T08:00:00+05:00", "end": "2026-10-01T11:00:00+05:00", "preset": null,
             "tz": "+05:00", "shift_grid_assumed": false, "clamped": false, "open": false},

  "uncovered": [],
  "points": 25, "points_usable": 25, "gaps": 0, "grid_step_s": 450.0,
  "method": "трапеции по фактическим интервалам между точками равномерной сетки историана; отрезок через недостоверную или пустую точку и разрыв длиннее допустимого не интегрируются",
```

При неполном покрытии — `status: "partial"`, `complete: false`, `total` — частичный итог за покрытые

итог за покрытые интервалы; полный расход за период неизвестен». Если ни одного отрезка не проинтегрировано
(все точки пустые/недостоверные) — `total: null`, `coverage_percent: 0.0`, заметка `FLOW_NONE_NOTE` = «нет ни

`FLOW_MAX_INTERVALS` = 20 каждый, при обрезке — заметка.

**Отказы**: `points` вне 20–96 — «points: от 20 до 96»; `unit` длиннее 20 знаков — «unit: строка до 20
знаков…»; у тега нет единицы ни в каталоге, ни в аргументе — «у тега … нет единицы в каталоге — уточните у
технолога единицу мгновенного расхода (например т/ч, кг/с, м3/ч) и передайте её в unit»; единица —
накопительный счётчик — «единица «…» — накопительный счётчик: показания уже накоплены, повторно не
интегрируются»; единица не расход — «единица «…» — не мгновенный расход (нужно количество за время, например
т/ч или кг/с)»; дискретный/неизвестный/вне списка тег — `MESSAGES["none"]`.

Переносимость: модуль `flow.py` и алгоритм интеграла — полностью переносимые (общая физика интегрирования
расхода); специфично для заказчика — ничего, кроме содержимого каталога единиц (`QUANTITY_UNITS`,
`TIME_UNITS` — общеинженерные, не завязаны на КДМ-1).

## `calc_formula` — расчёт по формуле над рядами тегов

Назначение: произвольный производный показатель (сумма, отношение, корреляция, регрессия…) по формуле над
рядами до 4 тегов — технолог или модель пишет формулу, арифметику считает код, не модель (чтобы модель не
ошиблась в уме и не отказывалась считать то, чего нет готовым калькулятором).

**Вход** (MCP-инструмент без HTTP-ручки; `CalcFormulaArgs`):

| Аргумент | Тип | Предел | По умолчанию |
|---|---|---|---|
| `tags` | список строк | 1–4 тега (`SERIES_MAX_TAGS`), по порядку — в формуле это `A, B, C, D` | — |
| `formula` | строка | 1–300 знаков (`FORMULA_CHARS`) | — |
| `period`/`start`/`end` | как у прочих | окно ≤ 31 суток | — |
| `points` | целое или `null` | 2–96 | `null` → наибольшее по бюджету: `min(96, 288 // число_тегов)` |

**Грамматика формулы** (`core/pcbk_core/formula.py`, разбор — `ast` с белым списком узлов, БЕЗ `eval`):

- Имена `A, B, C, D` — ряды тегов по порядку вызова (не больше, чем передано тегов — лишняя буква в формуле
  сверх числа тегов вызова, например `C` при одном теге, — отказ «formula: ряд C — тегов в вызове 1 (A —
  первый тег, B — второй, …)»).
- Числа, операторы `+ − × ÷` (принимаются и ASCII `+ - * /`, и типографские `× ÷ −`), `**`/`^` (показатель —
  число, не ряд, по модулю не больше `MAX_POWER` = 10), скобки, унарный минус; всё — поточечно: ряд с числом
  — к каждой точке, пустая точка любого операнда даёт пустую точку результата.
- `abs(x)` — поточечно.
- Свёртки ряда в число: `mean`, `sum`, `min`, `max`, `std` (выборочное σ, нужно ≥ 2 точек), `median`, `count`,
  `first`, `last`. Пустые точки ряда в свёртку не входят (не считаются нулём); если валидных точек нет вовсе —
  отказ «…(): в ряду нет ни одной годной точки».
- Парные свёртки (нужно ≥ `MIN_PAIRS` = 3 точек, где ОБА ряда не пусты на одной метке, иначе отказ): `corr(x,
  y)` — коэффициент Пирсона (один из рядов постоянен — не определена, отказ); `slope(y, x)`, `intercept(y, x)`,
  `r2(y, x)` — линейная регрессия `y = intercept + slope·x` (x постоянен — наклон не определён, отказ).
- Деление на ноль: в поточечной формуле — точка результата пустая (считается в `dropped`, не ошибка); в
  формуле, свёрнутой до чисел (например `mean(A) / (mean(A) − 3)`, где знаменатель — число 0), — ошибка
  `FormulaError` «formula: деление на ноль».
- Пределы разбора: длина строки ≤ `FORMULA_CHARS` = 300; число узлов разбора (`ast.walk`) ≤ `MAX_NODES` = 200
  («formula: слишком длинная»); только имена `A–D` и функции из списка — прочее имя («…: неизвестное имя
  «E» — ряды A, B, C, D, функции: …») или конструкция («…: недопустимая конструкция «Subscript»» и т. п. для
  любого узла ast вне белого списка — индексация, атрибуты, лямбды, тернарный оператор, вызовы не из списка
  функций — всё отклоняется); функции — по имени из списка, без именованных аргументов, с нужным числом
  аргументов (1 — для свёрток и `abs`, 2 — для парных).

**Ответ** (пример: `A` = `20FAKE_001_PV`, `B` = `20FAKE_003_PV`, формула `A + B`, 7 точек):

```json
{
  "tool": "calc_formula", "status": "ok", "formula": "A + B",
  "variables": {"A": {"tag": "20FAKE_001_PV", "description": "…", "unit": "л/час"},
                "B": {"tag": "20FAKE_003_PV", "description": "…", "unit": "л/час"}},
  "result_kind": "series", "result": null,
  "period": {"start": "…", "end": "…", "preset": null, "tz": "+05:00", "shift_grid_assumed": false,
             "clamped": false, "open": false},
  "points": 7, "method": "формула над рядами тегов на общей равномерной сетке историана; годная точка — значение есть и качество хорошее; пустая точка любого ряда даёт пустую точку результата; считает служба",
  "summary": {"count": 7, "mean": 12.0, "min": 3.0, "max": 21.0},
  "series": [["2026-10-01T08:00:00+05:00", 3.0], ["2026-10-01T08:30:00+05:00", 6.0], "…до 96 точек (FORMULA_SERIES_CAP)"],
  "notes": ["сетка равномерная: всплески короче шага не видны — истинные минимум, максимум и среднее даёт tag_period",
            "единицы служба не пересчитывает: результат — в единицах формулы над единицами тегов"],
  "cache": "miss"
}
```

Формула, свёрнутая до числа (например `mean(B) / mean(A)`), даёт `result_kind: "number"`, `result`: число
(округлено до 6 значащих цифр), без полей `summary`/`series`. `series` — ряд результата, не больше
`FORMULA_SERIES_CAP` = 96 точек; `dropped` (во внутреннем результате) — число точек, выпавших из-за деления
на ноль/переполнения, выводится заметкой «точек с делением на ноль или переполнением: `N` — выпали из
результата». Единицы служба НЕ пересчитывает: результат в единицах самой формулы над единицами тегов
(`FORMULA_UNITS_NOTE` — всегда в `notes`).

**Отказы**: `tags` вне 1–4 — «tags: не больше 4 тегов за вызов»; `formula` не строка/пустая/длиннее 300 —
«formula: нужна строка с формулой, например mean(A) / mean(B)» / «formula: не длиннее 300 знаков»; синтаксис
не разобран — «formula: не разобрана — проверьте скобки и знаки (+ - \* / \*\*)»; недопустимая конструкция —
«formula: недопустимая конструкция «…»»; неизвестное имя — «formula: неизвестное имя «…» — ряды A, B, C, D,
функции: …»; функция не из списка/с именованным аргументом/неверным числом аргументов — свои тексты (см.
выше); `points` не в 2–96 — «points: от 2 до 96»; все тега формулы вне белого списка/неизвестны/дискретны —
`MESSAGES["none"]`, до SQL; формула логически не считается после чтения данных (например ни одной годной
точки в ряду) — `refused` с текстом `FormulaError` (`status` при этом «refused», а не «error»).

Переносимость: модуль `formula.py` целиком переносимый (общий язык формул, никакой специфики КДМ-1); тегов
заказчика не знает вовсе — только буквы A–D на входе.

## Вкладка «Калькуляторы»

`core/pcbk_core/gateway/calc_api.py` — `POST /pcbk/api/calc/<tool>`: та же `DataService`, что у HTTP
`/api/data/` и MCP, вызывается в процессе шлюза, без HTTP-запроса к самому себе.

**Доступные инструменты** — только пять, список `CALC_TOOLS`:

| Маршрут | Инструмент службы | Модель аргументов |
|---|---|---|
| `POST /pcbk/api/calc/catalog_search` | `catalog_search` | `CatalogSearchArgs` |
| `POST /pcbk/api/calc/tag_now` | `tag_now` | `TagNowArgs` |
| `POST /pcbk/api/calc/tag_period` | `tag_period` | `TagPeriodArgs` |
| `POST /pcbk/api/calc/tag_series` | `tag_series` | `TagSeriesArgs` |
| `POST /pcbk/api/calc/calc_runtime` | `calc_runtime` | `CalcRuntimeArgs` |

**`calc_deviation`, `calc_spc`, `calc_flow_total`, `calc_formula` и `equipment` на вкладке НЕ доступны** —
только через MCP (модели агента) или, у `calc_deviation`, через HTTP `/api/data/calc_deviation` с токеном
места. Вызов любого другого имени (`save_agent` и т. п.) или одного из этих пяти по пути `/pcbk/api/calc/` —
`404` (`ERROR_NAMES[404]`).

**Проверки маршрута, по порядку** (`calc_router`): зона `front_only` (вне pcbk-front — 404) → настройка шлюза
(`configured`, иначе 503 «Шлюз не настроен: …») → сессия (`current_account`, иначе 401) → источник
(`origin_checked`, иначе 403, без строки журнала и счётчика) → инструмент в `CALC_TOOLS` (иначе 404) →
вызывающий по роли учётки (`caller_for`: преподаватель → `"teacher"`, студент с местом → `"student-NN"`,
прочее — 403 `ROLE_CALC_TEXT` = «Калькуляторы — только для студента с рабочим местом и преподавателя») →
служба подключена (`role.calc`, иначе 503 `CALC_DOWN_TEXT` = «Калькуляторы недоступны — служба данных не
подключена») → тело — объект JSON (иначе 400) → аргументы той же моделью, что у `/api/data/<tool>` (ошибка —
`refuse_args` службы, канал `web`, ответ 200 с отказом) → инструмент службы, ответ 200 при любом его статусе.
Предел частоты вызывающего общий для всех вкладок преподавателя (вызывающий один — `"teacher"`).

**Веб-форма** (`web/src/calc.ts`, `web/src/components/CalcPage.tsx`): 4 режима (`CalcMode`) —
`now`→`tag_now`, `period`→`tag_period`, `profile`→`tag_series`, `runtime`→`calc_runtime` (плюс отдельное поле
поиска тега — `catalog_search`); по умолчанию — режим `period`, период `prev_shift`, 24 точки профиля. Вкладка
сама не считает: числа — значения службы как есть, только в формате ru-RU (не больше 3 знаков после запятой;
малое ненулевое число — не «0», а 3 значащие цифры).

## Как добавить новый расчёт

Коротко: написать чистую функцию счёта (без ввода-вывода) в своём модуле `core/pcbk_core/`, как `spc.py`/
`flow.py`/`formula.py`; завести метод `DataService.calc_*` (или свой путь чтения, как у `calc_runtime`, или
путь `tag_series`, как у остальных пяти); описать инструмент в `TOOL_DESCRIPTIONS`/`CalcFlowArgs`-подобной
модели `mcp_server.py` для MCP и, если нужен прямой HTTP, — в `http_api.py`; если расчёт должен появиться на
вкладке «Калькуляторы» — добавить в `CALC_TOOLS` (`gateway/calc_api.py`) и в `MODE_CHOICES` (`web/src/calc.ts`)
с моделью аргументов. Подробный порядок и пример — [21-extending.md](21-extending.md).
