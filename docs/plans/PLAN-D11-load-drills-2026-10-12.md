**Goal:** доказать на сервере рядом с работающим Dify, что десять студентов одновременно не кладут ни сервер, ни
Dify, ни границы стенда, — и что любая поломка видна на странице состояния. Для этого:
- до нагрузки — **видно, что сервер на грани**: строка «Память сервера» знает свободную память, вытеснение в swap,
  давление памяти и убийства процессов по памяти вне мест и `core`; строка места говорит, **почему** оно
  перезапущено — «убит по памяти» или «сбой не по памяти»;
- **два независимых тормоза** жёстко останавливают прогон (прерывают ходы и усыпляют места) при **любом** условии
  «задели Dify»: свободная память ниже `MEM_FAIL_MIB`, swap сервера вырос от базы окна на порог, давление `full`
  выше порога, swap контейнеров Dify вырос на 256 МиБ, убийство по памяти вне мест. Прогонщик — по странице сторожа
  и чтению cgroup Dify; `core` — сам по `/proc` (и при мёртвом прогонщике, и после своего перезапуска). Оба проверены
  учением на тестовом стенде, затем на сервере; сроки мерятся по независимым источникам;
- **нагрузка лестницей** 2 → 5 → 10 мест ботами-студентами прогонщика Д8 по прогнозу памяти, с потолком денег из
  замеренной цены реплики; таблица памяти, swap, давления и Dify по ступеням; **успех 4** — по журналу службы и
  прокси; **успех 5 / неуспех 3** — каждый бот в конце видит только своё;
- **изоляция целиком** — один модуль на стенде и на сервере (места людей не будятся), плюс живой прогон шлюза Д5б;
- **сводные учения** — каталог по всем строкам страницы с проверкой полноты по коду, на сервере — со снимками.

**Architecture:**
- **Сторож (Д11а).** Модуль `watchdog/pcbk_watchdog/memory.py`: замер `/proc/meminfo`, `/proc/vmstat`,
  `/proc/pressure/memory`, история за час, причины перезапуска контейнеров (`OOMKilled` в окне `Restarting` и счётчик
  `oom_kill` ядра до и после осмотра). Строка «Память сервера» — пороги и тексты Д1, новые `warn`: убийства по памяти
  вне мест и `core`, давление `full` выше `PSI_FULL_MAX`, рост swap за 10 мин. «Идут учения: …» на странице.
- **Тормоз прогона в `core` (Д11а).** Только при `LLM_RUN_*`, раз в 5 с: свободно < порога; swap вырос от базы окна
  (`LLM_RUN_SWAP_BASE_MIB` или первая проверка) или за 10 мин на порог; давление `full` выше порога; `oom_kill` вырос
  от базы; файлы не читаются. Защёлка и базы хранятся в `llm_meta` по id прогона — переживают перезапуск `core`;
  снимает защёлку новый id прогона или команда администратора. Под защёлкой: вызовы модели мест прогона — 402
  `pcbk_run_halted`; пробуждение мест прогона — отказ (вход студента, кабинет, `restart` перезагрузки агентов);
  каждый такт уборщика усыпляет любое работающее место прогона.
- **Прогонщик Д8 в режиме нагрузки (Д11б).** Флаги `load`, `load_data`; пробные учётки `d11-probe-load-NN`; места ⊆

  контейнеров Dify, по тормозу `core`, по слепоте; живость сторожа — главным потоком; `prepare()` не будит места после

- **Тестовый стенд.** Двойники памяти, `vmstat`, давления и swap Dify (только `compose.test.yaml` и каталог теста);

- **Сервер — два окна.** Окно 1 (Д11в): выкладка, сверка с хостом, учения памяти и переполнения места, замер цены

  чтение.

## Критерии дня

Пороги — из `.env` сервера: `MEM_WARN_MIB` (2048), `MEM_FAIL_MIB` (1024), `SWAP_GROW_WARN_MIB` (512), `PSI_FULL_MAX`
(в В1 по базе: `max(5 %, 3 × база)`); `DIFY_SWAP_MAX_MIB` = 256; `LLM_RUN_USD` — потолок прогона Д8-R69. **База окна**
— swap сервера и swap контейнеров Dify, записанные в В1 шаг 3.

**Успех Д11 (все четыре дня вместе) — выполнены все:**

1. **Сервер на грани — видно.** Строка «Память сервера» показывает свободную память, swap и его рост за 10 мин,
   давление `some`/`full`, убийства по памяти вне мест и `core` за час; давление `full` выше порога 3 такта подряд —
   «внимание»; жёсткие условия (убийства, давление, swap) строка показывает и в полосе мягкого порога.
   Строка места после переполнения — «перезапущен: убит по памяти», после убийства процесса — «перезапущен: сбой не
   по памяти»; на сервере `oom_kill` вырос ровно на 1 (В1). Снимки — со стенда и с сервера.
2. **Тормоза сами и жёстко останавливают прогон** — учением на стенде, затем на сервере, без человека; сроки — по
   независимым источникам (R133):
   - **тормоз прогонщика:** от первого снимка сторожа с «сбоем» памяти (или «вытесняет в swap», «давление», «вне
     мест», или с жёсткими числами в `note` при «внимании» по порогу — давление с третьего снимка подряд) все места
     прогона остановлены (`State.FinishedAt`) не позже **60 с**; на стенде вдобавок — нет вызовов
     модели мест прогона, начатых позже **30 с** (журнал прокси);
   - **тормоз `core`:** не позже **20 с** (3 проверки подряд по 5 с) от падения памяти ниже порога (на сервере — от старта `core` с порогом
     учения) независимый вызов модели токеном места прогона получает 402 `pcbk_run_halted` (стенд; сервер — цикл
     `llmloop`, запущенный до пересоздания `core`); места прогона остановлены не позже **35 с**; пробуждение — 503 студенту и
     кабинету; так — и при мёртвом прогонщике, и после перезапуска `core` с тем же id прогона;
   - строка «LLM-прокси и бюджет» — «прогон остановлен тормозом памяти» или «тормоз прогона по памяти молчит»; на
     молчание прогонщик останавливается сам.
3. **Нагрузка.** На сервере боты-студенты идут на **десяти** местах (или на всех свободных — с прогнозом на 10 и
   решением владельца, R128); одновременная работа ступени «10» (минуты, в которые у каждого места был вызов модели)
   — **не меньше 3 минут**, цель — 10. За окно (от базы окна):
   - свободная память не ниже `MEM_FAIL_MIB`; swap сервера вырос меньше `SWAP_GROW_WARN_MIB`; swap контейнеров Dify
     вырос меньше `DIFY_SWAP_MAX_MIB`; давление `full avg10` не выше `PSI_FULL_MAX`; убийств по памяти вне мест и `core`

**Д11-R115 — причина перезапуска контейнера.** `RestartReasons` по строкам вида `container`. В такте: `v_before`,
`inspect`, `v_after`; `observe(component, inspect, v_before, v_after) -> (Reason | None, n)`:
- **база** — `v_before` последнего такта, где контейнер **не** в окне `Restarting` (работает или спит);
- **окно `Restarting`** (`Running` и `Restarting`): ожидающая причина — `"oom"` при `State.OOMKilled`, иначе
  `"crash"`; базу и «виден работающим» этот такт не меняет;
- **работает, не `Restarting`, `StartedAt` новый и `RestartCount` больше прежнего видимого** — перезапуск политикой:
  ожидающая причина, если была; иначе `"oom"` при `v_after > база`, иначе `"crash"`; `RestartCount` меньше прежнего —
  не сбой, запись сбрасывается; прежнего «виден работающим» нет — `None`;
- **объяснение:** при `"oom"` — `n = min(v_after − база, рост RestartCount)` (не меньше 1, если причина из
  `OOMKilled`), `MemHistory.attribute(n, now)`: необъяснённые приросты не старше `match_s`, старые первыми; не хватило
  — остаток ждёт приростов следующие `match_s` секунд.

import threading
from dataclasses import replace

from helpers import NoJournalWrite, wait_until
from pcbk_watchdog.main import MemState, WatchState, run_checks, run_loop


class RestartingDocker:
    """Первый осмотр — место работает; дальше — перезапущено, и за этот осмотр счётчик oom_kill вырос."""
    def __init__(self, vm):
        self.vm, self.n = vm, 0
    def inspect(self, name):
        self.n += 1
        if self.n == 1:
            return insp(running=True, started=T0 - timedelta(hours=1))
        if self.n == 2:
            self.vm.write_text("oom_kill 6\n")
        return insp(running=True, restarts=1, started=T0 - timedelta(seconds=5))
    def ping(self):
        pass


COMPS = [{"id": "memory", "title": "Память сервера", "kind": "memory"},
         {"id": "student-01", "title": "Рабочее место 01", "kind": "container", "container": "pcbk-student-01",
          "sleeping_ok": True}]

    vm = tmp_path / "vmstat"; vm.write_text("oom_kill 5\n")
    return vm, replace(SETTINGS, VMSTAT_PATH=str(vm), PRESSURE_PATH=str(tmp_path / "none"), **kw)


def test_run_checks_reads_oom_around_inspect(tmp_path):
    vm, settings = settings_with(tmp_path)
    docker, mem = RestartingDocker(vm), MemState(settings)
    run_checks(COMPS, docker, settings, T0 - timedelta(seconds=10), mem=mem)
    assert run_checks(COMPS, docker, settings, T0, mem=mem)[1].detail.startswith("перезапущен: убит по памяти")
    assert run_checks(COMPS, docker, settings, T0 + timedelta(minutes=1), mem=mem)[0].state == "ok"


def test_run_loop_wires_mem_state(tmp_path):                                # проводка, а не только run_checks
    vm, settings = settings_with(tmp_path, TICK_S=0.05)
    state, stop = WatchState(), threading.Event()
    t = threading.Thread(target=run_loop, args=(state, NoJournalWrite(), COMPS, RestartingDocker(vm), settings, stop))
    t.start()
    try:
        wait_until(lambda: state.snapshot and state.snapshot.checks[1].detail.startswith("перезапущен: убит по памяти"), 5)
    finally:
        stop.set(); t.join(5)

## Решения Д11б (Ruling)

**Д11-R119 — режим нагрузки прогонщика.** Ключи `"load": true`, `"load_data"` (R131) и поля базы окна:
`swap_base_mib`, `swap_grow_mib` (512), `dify_swap_base_mib`, `dify_swap_max_mib` (256), `mem_fail_mib` (1024),
`psi_full_max` (10.0; В1 переписывает оба из `.env` сторожа) — в серверных конфигах
обязательны (CLI `run` без них — `RunRefused("window_base")`), в конфигах стенда — по желанию.
- одна модель на многих местах; учётки — `LOAD_LOGIN = "d11-probe-load-{n:02d}"`; места ⊆ вызывающих; `run_brake`
  `watching` и свеж — иначе `RunRefused("brake")`; строка памяти на старте `ok` — иначе `RunRefused("memory")`;
- **сторож памяти** `MemoryGuard` — с `prepare()` до пробуждения мест, раз в `LOAD_MEM_POLL_S = 5.0`: `stand.status()`,
  `stand.health_llm()`, раз в 15 с — `stand.dify_swap_mib()`; точка в `OUT/memory.jsonl` (`t`, `checked_at`, `state`,
  `kind`, `free_mib`, `swap_used_mib`, `swap_grow10_mib`, `psi_full`, `oom_outside`, `dify_swap_mib`, `brake`,
  `brake_age_s`). Вердикт `guard_verdict(points, cfg, last_fresh_t, now_t)` — по последним точкам **разных** снимков
  сторожа (`checked_at`), последняя — текущая. **Решение — по числам, а не по тому, какой `detail` показала строка**
  (I-1 р3): в полосе «свободно меньше 2048 МиБ» давление, убийства и swap всё равно останавливают жёстко.
  - **жёстко `memory`:**
    - строка памяти `fail`/`unknown`; `warn` с `detail` ∈ {`MEM_SWAP_DETAIL`, `MEM_OOM_OUTSIDE_DETAIL`,
      `MEM_PSI_DETAIL`} (сторож уже выдержал своё удержание);
    - свободно (`detail`/`note` «свободно N МиБ») < `mem_fail_mib`;
    - убийств вне мест и `core` за час (`note` «…за час: K») > 0 — на старте строка `ok`, значит K = 0, и любое K > 0
      — новое;
    - swap за 10 мин (`note` «+G МиБ за 10 мин») ≥ `swap_grow_mib`; `swap_used_mib − swap_base_mib ≥ swap_grow_mib`
      (`note` «swap занят M МиБ»; рост **от базы окна**, B-1 р2);
    - давление `full` (`note` «full F %») > `psi_full_max` в `PSI_HOLD_POLLS = 3` разных снимках подряд (≈ 30 с при
      такте сторожа 10 с; один снимок, прочитанный трижды, — не три);
    - `dify_swap_mib − dify_swap_base_mib ≥ dify_swap_max_mib`; `run_brake.state == "halted"`;
  - **жёстко `brake`:** `run_brake` нет или `age_s > 30`;
  - **жёстко `blind`:** нет свежей страницы дольше `LOAD_BLIND_S = 30.0`; ошибка чтения swap Dify трижды подряд;
  - **мягко `memory_warn`:** `warn` по порогу и **ни одного** жёсткого числа.

  Нет части `note` — это условие не проверяется (части убийств нет при K = 0 по договору R114); формат `note` сверяет
  Б2 `test_note_numbers_parse_from_real_watchdog` на живом стенде.

  Тексты `detail` — значением, тест сверяет с `watchdog/pcbk_watchdog/memory.py`.
- **живость сторожа:** метка последнего опроса (`guard_at` в `progress.json`); главный поток на каждом шаге барьера
  проверяет `is_alive()` и возраст ≤ 30 с — иначе жёстко `blind`; `status OUT` → 1 при старой метке;
- **жёсткая остановка:** `_set_stop(reason, hard=True)`, `_abort_live()`, `stand.sleep_places(places)`;
  **`prepare()` проверяет `_hard` перед каждым входом и пробуждением места и выходит (I-6 р2)**; `close()` после

    def probe(self, net: str, addr: str, port: int) -> int:
        cmd = (f"docker run --rm --pull never --runtime={self.c['runtime']} --label {ONESHOT_LABEL} "
               f"--network {shlex.quote(net)} --read-only --cap-drop ALL --security-opt no-new-privileges:true "
               f"curlimages/curl:8.16.0 -sv --connect-timeout 3 -m 4 telnet://{addr}:{port}; echo \"rc=$?\"")
        r = self.sh(cmd)
        rc = int(r.stdout.rsplit("rc=", 1)[-1].strip() or 0)
        if rc in (125, 126, 127):                                          # сбой docker run — не «закрыто»
            raise RuntimeError(f"проба в {net}: docker run, код {rc}")
        return 1 if CONNECTED.search(r.stdout + r.stderr) else 0

    def counts(self, name: str, target_cmd: str) -> tuple[int, int]:
        """(положительный контроль на голом значении, счёт в цели); значение в вывод не идёт."""
        sd = shlex.quote(self.c["secrets_dir"])
        mk = PW_TO_FILE.format(sd=sd) if name == "bdrv-pw" else f"p={sd}/{shlex.quote(name)}"
        rm = '; rm -f "$p"' if name == "bdrv-pw" else ""
        ctrl = self.sh(f'{mk} && v=$(cat "$p") && printf "%s" "$v" | grep -c -F -f "$p"{rm}').stdout.split()
        hits = self.sh(f'{mk} && {{ {target_cmd}; }} | grep -c -F -f "$p"{rm}; true').stdout.split()
        return int(ctrl[0]) if ctrl else 0, int(hits[0]) if hits else 0

def core_modes() -> set[str]:                                               # источник правды — settings.py core

    for body in re.findall(r"^DRILL_[A-Z_]*MODES = frozenset\(\{(.*?)\}\)", src, re.M):
