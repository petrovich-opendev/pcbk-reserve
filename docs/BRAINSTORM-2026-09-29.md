## Б2. Архитектура чата. 29.09.2026: А — шлюз и контейнер на студента

Выбор совпал с рекомендацией. Отклонены: общий OpenCode на всех (память
экономит, но оболочка, файлы и MCP общие — первая ошибка шлюза даёт неуспех 1
или 3) и opencode-multiuser за основу (отдаёт терминал, без лицензии, против
решения 17).

* у каждого студента свой OpenCode в изолированном контейнере (gVisor), порт
  наружу не публикуется, сеть — только до LLM-прокси и службы данных;
* шлюз: вход и роли, белый список ручек, вырезает `permission`, `tools`,
  `system`, проверяет `agent`, пускает только к своим сессиям; преподавателю —
  только чтение;
* ключ OpenRouter — только в LLM-прокси (учёт расходов, потолок бюджета —
  см. Б4);
* пароль БДРВ — только в службе данных; агенты ходят к ней по MCP с токеном
  студента;
* агент-конструктор сохраняет агента через инструмент службы `save_agent`,
  служба проверяет схему и пишет файл; в контейнере каталог агентов — только
  чтение;
* цена — память: десять процессов, лимит на контейнер, простаивающие гасим.

Разбор — [`research/02-web-chat-opencode.md`](research/02-web-chat-opencode.md).

## Б3. Ветка OpenCode. 29.09.2026: v1.18.33

Выбор совпал с рекомендацией. Закрепляем v1.18.33 (стабильный канал,

* переезд на v2 — отдельной задачей после пилота, когда у v2 закроют ошибки
  памяти (#51340, #52041).

## Б4. Выбор модели. 29.09.2026: отбор на сценариях курса; бюджет до $1000

Выбор совпал с рекомендацией. Во время вопроса владелец поднял бюджет:
**«Бюджет на обучение в пределах $1000»** — решение 18 постановки (толкование:
на всё обучение, а не в месяц; заменяет $50 в месяц).

Прикидка, с которой задавался вопрос (грубая, без замеров): ~2 500 ходов в
месяц на 10 студентов, ход агента OpenCode — несколько обращений к модели по
20–40 тыс. токенов, итого 100–200 млн входных токенов в месяц. При $50 в месяц
годились только модели около $0,25 за миллион; при $1000 на обучение доступны и
модели среднего уровня.

Отбор — один дневной слайс плана, сразу после первого работающего чата:

* 3–4 модели разных ценовых уровней по ценам OpenRouter на день отбора;
* прогон через настоящий OpenCode на 12 сценариях: 4 — студент создаёт агента
  по своему узлу за один разговор (успех 1); 4 — «что сейчас» и «что за смену»,
  число совпадает с калькулятором (успех 2); 4 — ловушки: выдуманный норматив,
  чужой узел, просьба обойти службу;
* судья — Opus; на выходе таблица «качество × цена хода × прогноз на всё
  обучение» и выбор владельца;
* сценарии с данными заказчика в git не попадают;
* если в бюджет не укладывается ни одна годная модель — прихожу с цифрами.

# Проект подпроекта 1 по разделам

## Раздел 1. Компоненты и стек. 29.09.2026: согласован

1. **Веб** — React, TypeScript, assistant-ui. Студент: чат, свои агенты,
   состояние. Преподаватель: разговоры студентов только на чтение, учётные
   записи.
2. **Серверный слой** — одно приложение на Python (FastAPI), три роли; наружу
   слушает только шлюз, остальное — во внутренней сети:
   * шлюз — вход и роли, белый список вызовов к OpenCode студента, вырезание
     опасных полей, поток ответа;
   * LLM-прокси — ключ OpenRouter, расход по студентам, жёсткий стоп на
     бюджете;
   * служба данных (MCP) — калькуляторы, запрос по тегу, каталог тегов,
     `save_agent`, запись событий агента; пароль БДРВ, общий бюджет запросов и
     кэш — только здесь.
   Python — калькуляторы по ответу 1 постановки; один процесс — бюджет, кэш и
   учёт расходов в одном месте.
3. **Контейнеры студентов** — OpenCode v1.18.33 под gVisor, без root, лимит
   памяти, сеть только до серверного слоя; оболочка и правка файлов — заглушки;
   выгрузка в облако и автообновление выключены; старт при входе, остановка
   после 30 минут простоя.
4. **Хранение** — SQLite (учётки, учёт расходов, события агентов, журнал
   сторожа); файлы агентов на сервере, в контейнер — только чтение; разговоры —
   в томе контейнера студента.
5. **Сторож** — отдельный контейнер: серверный слой, свежесть историана, память
   сервера, падения контейнеров; Telegram владельцу; сердцебиение на hc-ping.com.
6. **Адрес** — на существующем входе `ai-lab.pcbk.ru`.

Проверено на сервере 29.09.2026 [П]:

* вход 80/443 держит nginx внутри Dify (контейнер `docker-nginx-1`),
  системного nginx нет. Наш веб встаёт за него отдельным `location` или
  поддоменом — это правка конфигурации Dify, делается с откатом; отдельный
  порт — только если его пропускает сетевой экран заказчика [?];
* Docker 29.7.2, cgroup v2, среда только `runc` — **gVisor (`runsc`) не
  установлен**, ставится в плане (нужен sudo); Ubuntu 22.04.5, ядро 5.15;
* пользователь `expert` управляет Docker без sudo;
* порт 3389 слушает, рядом `[::1]:3350` — это почти наверняка xrdp (удалённый
  рабочий стол); имя процесса без root не видно — подтвердить в плане
  (пункт 6 «Состава задачи»).

## Раздел 2. Пути пользователя. 29.09.2026: согласован, доля $100 на студента

1. **Вход** — логин и пароль в вебе (учётки заводит преподаватель); спящее
   рабочее место шлюз поднимает, студент видит «Готовлю рабочее место…»
   (холодный старт замерить живьём); при первом входе — предупреждение, что
   преподаватель видит разговоры.
2. **Создание агента в чате (успех 1)** — встроенный агент «Конструктор» (наша
   редакция генератора OpenCode под технологов) расспрашивает: узел, цель,
   вопросы; сам ищет теги в каталоге через службу; показывает черновик (имя,
   назначение, инструменты, правило «не выдумывать нормативы»); по согласию
   студента вызывает `save_agent`. Служба проверяет: инструменты только из
   нашего списка, без оболочки и правки файлов, имя уникально; пишет файл,
   перезагружает OpenCode студента — агент в списке.
3. **Число из БДРВ (успех 2)** — агент вызывает калькулятор или запрос по тегу с
   токеном студента; служба: белый список, бюджет запросов, кэш, SQL строит
   сама (одно LIKE на запрос); ответ — число, тег, период, время. Каждый вызов
   пишется событием агента (для преподавателя и слоя событий мнемосхем).
4. **Просмотр преподавателем** — список студентов, их разговоры и агенты только
   на чтение; студенты друг друга не видят.
5. **Деньги и отказ модели** — LLM-прокси считает цену каждого вызова по данным
   OpenRouter; 50 / 80 / 95 % бюджета — Telegram владельцу; на 100 % — понятное
   сообщение в чате. **Доля студента по умолчанию $100** ($1000 / 10),
   преподаватель перераспределяет; у агента — предел шагов на ответ.
   Отклонены: общий бюджет без долей; доля плюс дневной предел.
