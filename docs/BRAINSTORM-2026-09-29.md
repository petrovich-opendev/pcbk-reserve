## Б2. Архитектура чата. 29.09.2026: А — шлюз и контейнер на студента

Выбор совпал с рекомендацией. Отклонены: общий OpenCode на всех (память
экономит, но оболочка, файлы и MCP общие — первая ошибка шлюза даёт неуспех 1
или 3) и opencode-multiuser за основу (отдаёт терминал, без лицензии, против
решения 17).

* у каждого студента свой OpenCode в изолированном контейнере (gVisor), порт
  наружу не публикуется, сеть — только до LLM-прокси и службы данных;
* шлюз: вход и роли, белый список ручек, вырезает `permission`, `tools`,
  `system`, проверяет `agent`, пускает только к своим сессиям; преподавателю —
  только чтение;
* ключ OpenRouter — только в LLM-прокси (учёт расходов, потолок $50);
* пароль БДРВ — только в службе данных; агенты ходят к ней по MCP с токеном
  студента;
* агент-конструктор сохраняет агента через инструмент службы `save_agent`,
  служба проверяет схему и пишет файл; в контейнере каталог агентов — только
  чтение;
* цена — память: десять процессов, лимит на контейнер, простаивающие гасим.

Разбор — [`research/02-web-chat-opencode.md`](research/02-web-chat-opencode.md).

## Б3. Ветка OpenCode. 29.09.2026: v1.18.33

Выбор совпал с рекомендацией. Закрепляем v1.18.33 (стабильный канал,
releases/latest):

* чат — на готовом адаптере `@assistant-ui/react-opencode` (работает только с
  v1); его набор вызовов — основа белого списка шлюза;
* создание агента без диалога: `opencode agent create --path --description
  --mode --permissions`;
* запрет оболочки — своим инструментом-заглушкой вместо `bash`
  (`.opencode/tools/*.ts`);
* образ собираем сами (официальный есть только у v2);
* проверить живьём: новый агент виден после `POST /instance/dispose`;
* переезд на v2 — отдельной задачей после пилота, когда у v2 закроют ошибки
  памяти (#51340, #52041).
